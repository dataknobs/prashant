AI Agent Architecture Design

Six architectural decisions that shape an agent system: number of agents, planning, supervision, events, orchestration, and communication.

Key ideas
  • 1. Single vs. multi-agent
  • 2. Planner–executor
  • 3. Supervisor–worker
  • 4. Event-driven execution

1. Single vs. multi-agent

Start with one agent whenever possible. Add multiple agents only when work is genuinely parallel, requires distinct expertise, or becomes too broad for one context and toolset.

2. Planner–executor

Separate deciding what to do from carrying out the steps when tasks are long or benefit from re-planning.

3. Supervisor–worker

Use a coordinator to route work to specialized workers and aggregate outputs when multiple specialties are required.

4. Event-driven execution

Use events and queues for long-running, asynchronous, reactive, or externally triggered workflows.

5. Orchestration runtime

The runtime should manage state, retries, checkpoints, handoffs, policy gates, and observability—not merely call the model.

6. Communication protocols

Standardize tool access and agent-to-agent communication so integrations are explicit, authenticated, logged, and replaceable.
