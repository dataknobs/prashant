AGENTIC AI · STATE OF THE ART · SEPTEMBER 2026

From generating answers to getting work done

The capabilities that define agentic AI today: orchestration, memory and reasoning, execution, and governance

Prashant Dhingra · DataKnobs

Frame the talk: the last two years moved AI from a content generator to a goal-directed worker. The deck walks four capability layers and ends with what teams should build.

Generative AI answered prompts. Agentic AI pursues goals.

GENERATIVE AI · 2023–24

One prompt, one output

  • Stateless: forgets once the session ends
  • A human routes every step
  • Output is a draft a person must act on

AGENTIC AI · 2026

Goal in, outcome out

  • Runs a continuous perceive–plan–act loop
  • Manages multi-step workflows for hours or days
  • Acts on live systems within set permissions

The control loop at the core of every agent

01

Perceive

Read the goal, environment, tool results and memory

02

Plan

Break the goal into steps and pick the next action

03

Act

Call a tool, run code, browse or delegate to a sub-agent

04

Reflect

Check the result, update memory, re-plan if needed

The loop repeats until the goal is met, a step or budget limit is reached, or a human is pulled in.

01 · MULTI-AGENT ORCHESTRATION

A supervisor agent decomposes goals and delegates to specialists

  • The supervisor splits a high-level goal into subtasks and assigns each one
  • Specialists get narrow instructions, tools and permissions, so each works in a smaller, cleaner context
  • Reviewer agents critique outputs before results are merged or shipped

01 · MULTI-AGENT ORCHESTRATION

Agents share context in real time and run for days

Real-time context sharing

Shared memory, message queues and standard protocols (MCP for tools, A2A for agent-to-agent) let agents work in parallel without a human routing messages.

Long-horizon autonomy

Asynchronous runs over hours or days, with checkpoints, resume and re-planning as conditions change.

Delegation goes mainstream

In September 2026 Anthropic folded Cowork into Claude, which now decides on its own whether a request needs a chat reply or a longer agentic task.

02 · MEMORY AND REASONING

Recursive Language Models treat long context as something to explore

  1. The prompt is loaded as a variable in a Python REPL
  2. A root model writes code to search, slice and chunk it
  3. It recursively calls sub-model instances on the slices
  4. It combines their answers into the final result

MIT CSAIL reports inputs beyond 10M tokens at comparable or lower cost. On one 132K-token benchmark, an RLM using GPT-5-mini scored 64.9% vs 30.3% for GPT-5 called directly.

A useful distinction

RLMs are an inference strategy, not a new model class. Hidden, self-verifying reasoning comes from reasoning models with extended thinking. The two combine well: a reasoning model makes a stronger root.

Source: Zhang, Kraska & Khattab, arXiv:2512.24601

8

02 · MEMORY AND REASONING

Agents ground their reasoning in live data

Agentic retrieval

The agent decides when and what to look up (web, internal docs, knowledge graphs) and refines its queries as it goes.

Verify before acting

Facts are checked against systems of record before the agent writes, spends or sends anything.

The caveat

Grounding reduces hallucination; it does not remove it. Sources can be stale, wrong or carry prompt injections.

03 · EXECUTION AND TOOLS

Typed tool contracts let agents change live systems

From suggestion to action

  • Tools declared with typed schemas the agent can validate against
  • MCP servers discovered and called at runtime
  • Plans revised when a call fails or returns something unexpected
  • Real side effects: refunds, database edits, deployments

04 · GOVERNANCE AND SECURITY

Bounded loops and calibrated escalation keep autonomy safe

Circuit breakers and loop bounds

  • Maximum steps, time and spend per run
  • Detection of repeated or oscillating actions
  • Automatic halt when a policy threshold is crossed
  • Sandboxes and dry runs for destructive actions

Adaptive escalation

  • Agent estimates its own confidence
  • Routine checks are verified by the agent itself
  • Novel, irreversible or high-value actions go to a human
  • People supervise the exceptions, not every output

What this means for teams building agents

1

Design the whole harness (loop, memory, tools, limits), not just the prompt.

2

Start with a supervisor and a few narrow specialists; add agents only when it measurably helps.

3

Give every agent an identity and least-privilege tools from day one.

4

Budget autonomy with step and spend caps and clear escalation rules.
