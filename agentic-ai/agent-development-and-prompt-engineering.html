Agent Development & Prompt Engineering

Prompt engineering is both a writing discipline and an operational discipline: define who the agent is, what it should do, the boundaries it must respect, and then manage those prompts like production code.

Overview

From prompt craft to Prompt-Ops

The deck divides the practice into six levers. The first four shape the prompt itself; the last two turn prompts into versioned, tested infrastructure.

1

System Prompt Design

Set the agent's role, stable context, ground rules, capabilities, tools, and output format.

2

Agent Instructions

Tell the agent precisely what to do, how to do it, and what successful completion means.

3

Behavioral Constraints

Define the lines the agent must not cross and back prompt rules with code-level enforcement.

4

Persona Design

Shape a consistent voice and character without allowing persona to replace real constraints.

5

Prompt Versioning

Track immutable versions, diffs, promotions, audit history, and fast rollback.

6

Prompt Testing

Run each prompt version against a dataset, score outputs, compare with a baseline, then ship or iterate.

Treat prompts like code. Small wording changes can shift behavior, so review diffs, test every change, and make rollback routine.
Craft

System Prompt Design

The system prompt is the agent's charter: stable, top-level context that frames every response.

  • Define role and identity, domain context, capabilities and tools.
  • State rules and guardrails clearly, then specify output format.
  • Keep dynamic data downstream and keep the system prompt lean.
  • Use structure the model can parse, such as clear sections or XML tags where appropriate.
Craft

Agent Instructions

Ambiguous instructions force the model to fill gaps with guesses. Good instructions reduce that space for interpretation.

  • Be specific and unambiguous; prefer positive framing.
  • Specify fields, length, structure, ordering, and success criteria.
  • For complex work, break the task into ordered steps.
  • Use examples where they clarify the expected behavior.
Vague

“Summarize this document.”

Specific

“Summarize in exactly 3 bullets, each under 15 words, focused on financial risks. Output as a markdown list.”

Craft

Behavioral Constraints

Constraints define the boundaries the agent must not cross, regardless of what a user asks.

  • Constrain scope, safety, sensitive data, actions, tone, and escalation.
  • Prompt-level rules alone are not enough; layer validation and guardrail models.
  • Put irreversible or costly action controls in code, not only in prompt text.
  • Red-team constraints and treat a bypass as a defect.
Craft

Persona Design

Persona is the voice and character users experience. It can improve consistency and brand fit, but it should never substitute for actual policy or controls.

  • Specify name and role, tone and voice, style, values, and boundaries.
  • Avoid over-acting a character when it reduces clarity or accuracy.
  • Use a reusable persona card so the specification stays consistent.

Prompt-Ops

Make prompts versioned, testable infrastructure

Prompt craft determines the behavior you want. Prompt-Ops makes that behavior reproducible, promotable, observable, and reversible.

Prompt-Ops

Prompt Versioning

A prompt version captures more than words. It should reproduce the conditions that produced the behavior.

Author & edit
Commit immutable version
Staging eval gate
Production
  • Capture prompt text together with model, parameters, tools, and metadata.
  • Use immutable IDs and clear diffs so behavior is reproducible and debuggable.
  • Promote through environments with quality gates and make rollback immediate.
Tools named in the deck: LangSmith · Langfuse · PromptLayer · Braintrust · Promptfoo · Maxim AI
Prompt-Ops

Prompt Testing

Agent outputs are non-deterministic, so testing is based on datasets, scorers, baselines, and regression checks rather than exact-string assertions.

Dataset cases
Run variants
Score outputs
Compare to baseline
Ship or iterate

What makes a good eval

  • Typical queries, edge cases, and adversarial inputs.
  • Deterministic checks for structure plus model-based scoring for quality.
  • A baseline that new versions must beat.
  • Regression testing so a fix does not quietly break something else.

Close the loop

  • Score samples of production traffic with the same logic.
  • Turn low-scoring cases into new eval cases.
  • Grow coverage so known failures do not resurface.
  • Prefer grounded scorers over subjective impressions.
