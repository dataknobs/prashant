Trust boundaries and credential design

Read slide 5 text
S E CU R I TY Trust boundaries and credential design Do not let the model become an authority or receive reusable secrets. AGENTIC AI / ASSURANCE ARCHITECTURE 05 Untrusted content User messages, retrieved pages, emails, files and tool outputs remain data. Mark provenance and resist instruction injection. Agent execution context Short-lived scoped identity, tenant context, approved action set, time/budget quota and workflow checkpoint. Privileged resources APIs, database writes, payments and external messages are reached only through authenticated, server-side tool adapters. Default deny Least privilege No plaintext secrets in prompts

90-day delivery roadmap

Read slide 23 text
B UI L D PL A N 90-day delivery roadmap Promote autonomy only after you can test, govern and recover it. AGENTIC AI / ASSURANCE ARCHITECTURE 23 Days 1–30 FOUNDATION Identify critical actions; define tool contracts; risk tiers; baseline traces and eval set. Days 31–60 CONTROLLED PILOT Deploy policy gateway, approval queues, replay suite, spend caps and read-only pilot. Days 61–90 GATED PRODUCTION Canary reversible actions; measure task-level economics; run incident drills; expand by risk tier. Release criterion: demonstrated task value + measurable policy compliance + tested human override and shutdown path.

Architecture review checklist

Read slide 24 text
B E S T PRA C TI C E S Architecture review checklist Use these questions during design review and production readiness assessments. AGENTIC AI / ASSURANCE ARCHITECTURE 24 Can any agent bypass the tool gateway or use a credential directly? Is every effectful action authorized and attributable to a principal? Are risky actions paused, reviewed, time-bound and revalidated? Do evals cover full trajectories, tool side effects and attacks? Can we replay a run and link each tool call to an outcome? Are budgets, idempotency, rollback and emergency stop tested? Do cost improvements retain outcome quality and policy compliance?
