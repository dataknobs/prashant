The central principle: improve behavior without surrendering

Read slide 2 text
F O U N D AT I O N S The central principle: improve behavior without surrendering control A self-evolving agent may propose changes; an independent system decides what is allowed to run. SELF-EVOLVING AGENTS • HARNESS × GOVERNANCE 02 Agent execution plane Performs tasks under bounded context, tool permissions, budgets and runtime checks. Evolution plane Analyzes evidence and generates candidate memory, prompt, skill or workflow changes. Governance control plane Owns immutable policy, independent validation, approval, release and rollback. Never let the agent edit the same controls that constrain its actions.

Context and memory governance

Read slide 10 text
C O N T E X T & M E M O R Y Context and memory governance Self-evolution often begins in memory; that is also where contamination can become persistent. SELF-EVOLVING AGENTS • HARNESS × GOVERNANCE 10 Write policy Only persist validated, task-relevant facts. Enforce consent, tenancy boundaries and retention. Trust policy Record origin, confidence, timestamp and source. Untrusted text cannot create instructions. Lifecycle policy TTL, correction, deletion, conflict handling, revalidation and safe compaction. Memory entries are evidence; they are not automatically policy or system instructions.

Operational controls: governance in production

Read slide 19 text
O P E R AT I O N S Operational controls: governance in production The release process is only half the story; runtime autonomy must remain bounded. SELF-EVOLVING AGENTS • HARNESS × GOVERNANCE 19 Budgets + kill switch Maximum steps, tokens, tool calls, wall time, financial exposure; emergency disable. Reliability controls Checkpoint, retry limits, circuit breaker, safe fallback, idempotency and compensation. Drift response Detect data, task and policy drift; pause learning; revert to baseline and retrain evaluation. Separate “stop agent execution” from “stop evolution and promotion.” Both must exist.

The first 90 days: build a governed evolution pilot

Read slide 23 text
I M P L E M E N TAT I O N The first 90 days: build a governed evolution pilot A phased approach to establishing control before autonomy. SELF-EVOLVING AGENTS • HARNESS × GOVERNANCE 23 Days 1–30: Foundations Choose one low-risk change surface. Define policies, identities, evidence schema, trace lineage and baseline evaluations. Days 31–60: Controlled candidates Create candidate registry, evaluation harness, adversarial suites, approval packets and rollback. Days 61–90: Pilot & learn Run shadow mode and narrow canary. SLIDE 24 / 24

The bottom line: evolution is a governed release process

Read slide 24 text
S U M M A R Y The bottom line: evolution is a governed release process Design the agent to learn; design the platform to retain accountability. SELF-EVOLVING AGENTS • HARNESS × GOVERNANCE 24 Harness Controls each run: identity, context, tool access, policy enforcement, human pause and observability. Evolution engine Generates candidates from evidence; cannot mutate serving policy or deploy itself. Governance plane Independent evaluation, approvals, risk-tiered release, audit, continuous monitoring and rollback. Agents may recommend improvements. The organization remains accountable for every deployed change.
