AI HARNESS • ENTERPRISE REFERENCE 02 Model Interprets instructions, reasons about information, and proposes responses or actions. What is an AI harness?

Read slide 3 text
0 2 / D E F I N I T I O N What is an AI harness? The runtime substrate that mediates model ↔ world interaction. AI HARNESS • ENTERPRISE REFERENCE 03 Observe Select inputs, retrieve evidence, read memory, normalize tool outputs. Decide Assemble model context, choose model, manage response schemas and agent steps. Act Authorize and execute tools; pause for human review; isolate risky operations. Recover Persist checkpoints, retry safely, resume paused work and handle failures. Measure Capture traces, quality outcomes, cost, latency, and feedback. Improve Use evaluation findings to adjust prompts, tools, policy, model routing and context.

The boundary: model vs. harness

Read slide 4 text
0 3 / R E S P O N S I B I L I T Y S P L I T The boundary: model vs. harness AI HARNESS • ENTERPRISE REFERENCE 04 Model decides (proposes) Which facts are useful, how to reason, what next step may help, what tool to request. Harness decides (enforces) Which model, exact context, tool permission, spending limits, approval, retries and state. Systems decide (commit) Database constraints, business validation, transaction integrity, identity and audit. Never rely on a model-generated “permission granted” statement as authorization.

Memory is not the context window

Human-in-the-loop: approval, not decoration

Read slide 12 text
11 / H I T L Human-in-the-loop: approval, not decoration AI HARNESS • ENTERPRISE REFERENCE 12 ALLOW Read-only, bounded, low-risk work proceeds automatically. REVIEW Payments, external communication, sensitive changes or uncertainty pause for approval. DENY / ESCALATE Forbidden or high-impact requests are blocked or routed to owners. Approve a specific action payload, not a vague agent intention. Bind approval to the exact parameters.

SLIDE 16 / 27

Cost optimization belongs in the harness

Read slide 16 text
1 5 / U N I T E C O N O M I C S Cost optimization belongs in the harness AI HARNESS • ENTERPRISE REFERENCE 16 Cache smartly Keep stable prompt prefixes; reuse permitted retrieval and computation. Reduce context Tool-output filtering, just-in-time retrieval, structured compaction. Route models Choose model and reasoning effort based on task difficulty and risk. Limit loops Max turns, max tool calls, timeout and graceful fallback. Batch appropriately Process non-urgent evaluation and background jobs asynchronously. Optimize the outcome Track $ / successful task, not just $ / million tokens. Optimize against a fixed eval set; cheaper but less reliable can cost more overall.

Failure modes and resilience patterns

Read slide 17 text
1 6 / R E L I A B I L I T Y Failure modes and resilience patterns AI HARNESS • ENTERPRISE REFERENCE 17 Tool failure Retry with jitter for safe operations; circuit break persistent faults. Duplicate side effects Idempotency keys, outbox patterns and reconciliation. Run interruption Checkpoint state; resume from last verified stage. Infinite agent loops Step ceilings, progress checks, dead-end detectors. Untrusted content Segregate content from instructions; constrain tool outputs. Partial success Compensating actions; escalate irreversible operations.

Design principles to remember

Read slide 26 text
2 5 / TA K E AWAY S Design principles to remember AI HARNESS • ENTERPRISE REFERENCE 26 Treat model output as proposals Policy and business systems are the authority for actions. Design context deliberately Retrieve and compact; do not dump everything into the prompt. Gate every side effect Authorize the specific payload before execution. Measure successful outcomes Quality and safety matter alongside cost and speed. Keep runs reconstructable Persist state, traces, versions and decision evidence. Improve the complete system Model + harness + environment must be evaluated together.
