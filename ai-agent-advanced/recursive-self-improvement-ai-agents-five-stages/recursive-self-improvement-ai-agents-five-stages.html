Executive summary

Read slide 2 text
Executive summary Recursive improvement is an evidence pipeline—not unlimited permission to self-modify. OVERVIEW RECURSIVE SELF-IMPROVEMENT • ARCHITECTURE & GOVERNANCE 02 What changes The agent moves from solving tasks to proposing and testing durable improvements to its own behavior. What compounds Better skills, better curricula, better diagnosis and eventually better improvement strategies. What must not move Independent objectives, authorization, evaluation integrity and production release authority. The improvement loop should be more constrained than the execution loop. The more powerful the self-editing mechanism, the stronger the independent checks.

SLIDE 3 / 38

What counts as recursive self-improvement?

Read slide 3 text
What counts as recursive self-improvement? Separate adaptation, durable improvement, and improving the improver. DEFINITIONS RECURSIVE SELF-IMPROVEMENT • ARCHITECTURE & GOVERNANCE 03 1 Response refinement Rewrites a single answer; no persistent capability change. 2 Experience adaptation Learns from a run; updates memory or reusable skills. 3 System modification Changes prompts, planner, tools or workflow and validates results. 4 Recursive improvement Changes the search, diagnosis, or improvement machinery itself. Important: model-weight retraining is not required. Persistent changes to skills, memory, tools or orchestration can already alter agent behavior.

Stage 1: the operating contract

Stage 1: the operating contract Six fields establish a safe baseline for later evolution. STAGE 1 RECURSIVE SELF-IMPROVEMENT • ARCHITECTURE & GOVERNANCE 08 Objective A measurable business outcome, with explicit exclusions. SLIDE 13 / 38

Self-critique vs. causal diagnosis

Read slide 13 text
Self-critique vs. causal diagnosis The same model can invent a convincing explanation for an error it has not isolated. STAGE 2 RECURSIVE SELF-IMPROVEMENT • ARCHITECTURE & GOVERNANCE 13 Weak loop: “looks better” Agent critiques its own answer → rewrites it → grades itself → declares success. Risk: style changes conceal the original failure; evaluator and candidate share the same blind spots. Strong loop: “proved better” Replay trace → create explicit hypothesis → compare variants on fixed and unseen tasks → inspect side effects. Evidence: task outcome and independent checks improve without regressions. Rule: the agent may write the diagnosis; a separate harness must verify it. Use code-based, model-based and human graders where appropriate.

SLIDE 18 / 38

What makes a self-designed curriculum useful?

Read slide 18 text
What makes a self-designed curriculum useful? Generating more tests is not enough; the new tasks must remain relevant and discriminative. STAGE 3 RECURSIVE SELF-IMPROVEMENT • ARCHITECTURE & GOVERNANCE 18 Coverage Does it target capability gaps and infrequent failure cases? Validity Do generated tasks have correct, checkable answers? Realism Does the simulator preserve real-world constraints? Difficulty control Does the curriculum adapt with observed ability? Security isolation Are synthetic tools and data fenced from production? Novelty discipline Are holdout tasks truly unseen—not memorized variants? A curriculum is a source of training evidence, not an authority that sets its own passing score. Independent benchmark owners retain the right to reject generated tasks.

SLIDE 23 / 38

Why “the real world will teach it” is not enough

Read slide 23 text
Why “the real world will teach it” is not enough Feedback pipelines can systematically teach the wrong behavior. STAGE 4 RECURSIVE SELF-IMPROVEMENT • ARCHITECTURE & GOVERNANCE 23 Selection bias Users who complain are not representative of all tasks. Confounding Changes in policy or traffic can appear as agent progress. Reward hacking Agent optimizes visible approval signals instead of outcomes. Privacy contamination Sensitive content leaks into reusable memory or tests. Safety drift Short-term task success hides worsening risk exposure. Stale labels Previously correct outputs become wrong when facts change. Treat production feedback as a governed dataset—not as a direct write channel into agent behavior. Version, review, sample and re-evaluate every promoted learning artifact.

SLIDE 29 / 38

The meta-evaluation trap: optimizing the test instead of the outcome

Read slide 29 text
The meta-evaluation trap: optimizing the test instead of the outcome At Stage 5, the improver may learn how to exploit evaluator weaknesses. FAILURE MODE RECURSIVE SELF-IMPROVEMENT • ARCHITECTURE & GOVERNANCE 29 Failure: grader capture Agent discovers that longer explanations receive higher scores. It produces more elaborate outputs, while factual quality and task success stay flat or deteriorate. Defense: independent evidence Protect sealed holdouts; rotate unseen tasks; measure downstream outcomes; use diverse graders and periodic expert calibration. Improvement can be accepted only when it generalizes beyond the tests used to create it. Freeze scoring rules for each experiment and audit who can change them.

Governance: retain human and institutional authority

Governance: retain human and institutional authority Improving capability must not imply permission to redefine the mission or release gates. GOVERNANCE RECURSIVE SELF-IMPROVEMENT • ARCHITECTURE & GOVERNANCE 31 Allowed automatically Store bounded task-local state; propose fixes; generate sandbox tasks; run non-destructive offline evaluations. SLIDE 32 / 38

Evaluation stack: proving the improvement actually helped

Read slide 32 text
Evaluation stack: proving the improvement actually helped Never rely on a single self-generated score, one run, or one benchmark. EVALUATION RECURSIVE SELF-IMPROVEMENT • ARCHITECTURE & GOVERNANCE 32 Outcome tests Did the real task succeed? Verify external state where possible. Trajectory tests Were tools, steps, intermediate decisions and approvals correct? Regression tests Did previously working tasks or safety requirements deteriorate? Adversarial tests What happens under prompt injection, bad data and tool failures? Statistical repeats Run multiple trials; report variance and uncertainty. Human calibration Use expert review to validate subjective or high-impact grading. Evidence packet = version diff + measured outcomes + side effects + residual risks + rollback plan. Include the exact artifact, dataset, evaluator and policy versions.

Metrics that indicate genuine compounding improvement

Read slide 33 text
Metrics that indicate genuine compounding improvement Measure business utility and control quality—not just benchmark accuracy. MEASUREMENT RECURSIVE SELF-IMPROVEMENT • ARCHITECTURE & GOVERNANCE 33 Task quality Successful tasks / attempts; weighted by severity and business value. Learning yield Accepted improvements per candidate and per evaluation dollar. Generalization Gain on protected unseen tasks and new data distributions. Reliability Rollback rate, incident frequency, intervention burden. Economics Cost, latency and tokens per successfully completed task. Governance Policy violations, denied tool calls, approval and audit completeness. North star: sustained improvement in quality-adjusted outcomes with bounded safety risk and total operating cost.

90-day pilot: start with diagnosis, not recursive code changes

Read slide 35 text
90-day pilot: start with diagnosis, not recursive code changes Prove that closed-loop improvement works on one low-risk domain before raising autonomy. IMPLEMENTATION RECURSIVE SELF-IMPROVEMENT • ARCHITECTURE & GOVERNANCE 35 DAYS 01–30 Baseline + traces Pick 1 workflow. Define success and failure taxonomy; instrument harness; seed known and unseen tests. DAYS 31–60 Diagnosis + candidate eval Generate bounded repair proposals; evaluate offline; build immutable candidate registry and approval gates. Maturity decision: which stage should we build next?

Read slide 36 text
Maturity decision: which stage should we build next? Advance only when the current stage produces trustworthy evidence. DECISION FRAMEWORK RECURSIVE SELF-IMPROVEMENT • ARCHITECTURE & GOVERNANCE 36 Stage 1 → 2 Do we have reliable task outcomes and full execution traces? Stage 2 → 3 Are diagnosis and repairs validated by independent tests? Stage 3 → 4 Are generated tasks representative, safe and high value? Stage 4 → 5 Can we isolate learning signals and defend against reward hacking? Stage 5 Can we prove meta-improvement without agent-controlled evaluators? If the answer is “not yet,” improve the measurement and governance infrastructure before adding autonomy.
