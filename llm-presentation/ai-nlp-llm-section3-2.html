Structured Output

Turn LLM responses from prose into reliable, machine-readable data. Learn JSON generation, schema enforcement, function calling, and validation :: the foundation of production AI systems.

3.2.0

Why Structured Output Matters

Prose is for humans. Production software needs data. Structured output generation bridges the gap between LLM's generative power and the typed, validated data structures your code expects.

When an LLM returns a paragraph, your application must parse it :: a brittle, error-prone process. When it returns structured JSON matching a known schema, your code can parse, validate, and act on it programmatically. This is the difference between a demo and a production system.

Unstructured vs Structured Pipeline

ARCHITECTURE

Reliability

vs. free-form

JSON is parseable deterministically. Prose requires regex or another LLM call to parse. Format errors drop to near-zero with schema enforcement.

Composability

pipeline integration

Structured outputs plug directly into databases, APIs, and downstream code. The LLM becomes a typed function, not a text generator.

Validation

catch errors early

Schemas let you validate types, ranges, required fields, and business rules :: catching hallucinations and format drift before they reach production.

3.2.1

JSON Output Generation

The simplest form of structured output: instruct the model to return JSON, specify the exact schema, and parse the result. Three levels of reliability :: each more robust than the last.

1Level 1 :: Prompt-Only (Fragile)

Simply ask for JSON. Works most of the time, but the model may add markdown fences, explanations, or deviate from your schema under pressure.

level1_prompt_only.py
PYTHON 
import json
from anthropic import Anthropic

client = Anthropic()

def extract_contact(text: str) -> dict:
    response = client.messages.create(
        model="claude-sonnet-4-20250514",
        max_tokens=512,
        system="""Extract contact information and return ONLY valid JSON.
No markdown, no explanation, no code fences.
Schema: {"name": str, "email": str|null, "phone": str|null, "company": str|null}""",
        messages=[{"role": "user", "content": text}]
    )
    raw = response.content[0].text.strip()
    # Strip markdown fences if the model added them anyway
    if raw.startswith("```"):
        raw = raw.split("\n", 1)[1].rsplit("```", 1)[0].strip()
    return json.loads(raw)  # ← raises JSONDecodeError if model misbehaves

result = extract_contact(
    "Hi I'm Sarah Chen, lead engineer at Vertex Systems. "
    "Reach me at s.chen@vertex.io or +1-415-555-0192."
)
print(result)
# {"name": "Sarah Chen", "email": "s.chen@vertex.io",
#  "phone": "+1-415-555-0192", "company": "Vertex Systems"}

2Level 2 :: Schema in Prompt (More Robust)

Include the full JSON Schema in the system prompt with types, constraints, and examples. Dramatically reduces format deviations.

level2_schema_prompt.py
PYTHON 
import json

INVOICE_SCHEMA = {
    "type": "object",
    "required": ["invoice_number", "vendor", "total_amount", "currency", "line_items"],
    "properties": {
        "invoice_number": {"type": "string"},
        "invoice_date":   {"type": "string", "format": "date"},
        "due_date":        {"type": "string", "format": "date", "nullable": True},
        "vendor": {
            "type": "object",
            "properties": {
                "name":    {"type": "string"},
                "address": {"type": "string", "nullable": True},
                "tax_id":  {"type": "string", "nullable": True},
            }
        },
        "line_items": {
            "type": "array",
            "items": {
                "type": "object",
                "properties": {
                    "description": {"type": "string"},
                    "quantity":    {"type": "number"},
                    "unit_price":  {"type": "number"},
                    "amount":      {"type": "number"},
                }
            }
        },
        "subtotal":     {"type": "number", "nullable": True},
        "tax_amount":   {"type": "number", "nullable": True},
        "total_amount": {"type": "number"},
        "currency":     {"type": "string", "enum": ["USD", "EUR", "GBP", "JPY"]},
    }
}

SYSTEM = f"""You are a document parser. Extract invoice data and return ONLY valid JSON.
Match this JSON Schema exactly:
{json.dumps(INVOICE_SCHEMA, indent=2)}
Rules:
- All monetary values as numbers (not strings)
- Dates in YYYY-MM-DD format
- null for any field not found in the document
- Return ONLY the JSON object, no other text"""

3Level 3 :: Native Structured Outputs (Most Reliable)

Modern APIs support native structured output modes that constrain the token generation to match your schema :: the model cannot physically produce invalid JSON.

level3_native_structured.py
PYTHON 
# ── Approach A: OpenAI Structured Outputs (JSON Schema enforcement) ──
from openai import OpenAI
from pydantic import BaseModel
from typing import Optional

client = OpenAI()

class LineItem(BaseModel):
    description: str
    quantity:    float
    unit_price:  float
    amount:      float

class Vendor(BaseModel):
    name:    str
    address: Optional[str] = None
    tax_id:  Optional[str] = None

class Invoice(BaseModel):
    invoice_number: str
    invoice_date:   str
    due_date:       Optional[str] = None
    vendor:         Vendor
    line_items:     list[LineItem]
    subtotal:       Optional[float] = None
    tax_amount:     Optional[float] = None
    total_amount:   float
    currency:       str

response = client.beta.chat.completions.parse(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": "Extract invoice data from the document."},
        {"role": "user", "content": invoice_text}
    ],
    response_format=Invoice,   # ← constrained generation
)

invoice: Invoice = response.choices[0].message.parsed  # typed Python object
print(f"Total: {invoice.currency} {invoice.total_amount}")
print(f"Items: {len(invoice.line_items)}")

# ── Approach B: Anthropic with explicit JSON schema in tool ──
from anthropic import Anthropic
aclient = Anthropic()

response = aclient.messages.create(
    model="claude-sonnet-4-20250514",
    max_tokens=2048,
    tools=[{
        "name": "extract_invoice",
        "description": "Extract structured invoice data",
        "input_schema": Invoice.model_json_schema()
    }],
    tool_choice={"type": "tool", "name": "extract_invoice"},
    messages=[{"role": "user", "content": invoice_text}]
)

tool_use = next(b for b in response.content if b.type == "tool_use")
invoice  = Invoice(**tool_use.input)  # validated Pydantic object
3.2.2

Schema-guided Generation

JSON Schema gives you a formal grammar for your output. Mastering schema design :: types, enums, nested objects, arrays, constraints :: is what separates amateur from production-grade structured output prompts.

SSchema Design Patterns

schema_patterns.py
JSON SCHEMA 
# ── Pattern 1: Enum constraints (limit model's choices) ──
{
  "sentiment": {
    "type": "string",
    "enum": ["POSITIVE", "NEGATIVE", "NEUTRAL", "MIXED"]
  }
}

# ── Pattern 2: Numeric ranges (prevent hallucinated values) ──
{
  "confidence": {
    "type": "number",
    "minimum": 0.0,
    "maximum": 1.0
  },
  "year": {
    "type": "integer",
    "minimum": 1900,
    "maximum": 2100
  }
}

# ── Pattern 3: Nullable fields (explicit about missing data) ──
{
  "phone": {
    "oneOf": [
      {"type": "string", "pattern": "^\\+?[\\d\\s\\-()]+$"},
      {"type": "null"}
    ],
    "description": "Phone number in any format, or null if not present"
  }
}

# ── Pattern 4: Typed arrays with min/max items ──
{
  "tags": {
    "type": "array",
    "items": {"type": "string", "maxLength": 50},
    "minItems": 1,
    "maxItems": 10
  }
}

# ── Pattern 5: Discriminated unions (polymorphic results) ──
{
  "event": {
    "oneOf": [
      {
        "type": "object",
        "properties": {
          "type": {"const": "purchase"},
          "amount": {"type": "number"}
        }
      },
      {
        "type": "object",
        "properties": {
          "type": {"const": "refund"},
          "reason": {"type": "string"}
        }
      }
    ]
  }
}
Schema Design Tips

Use enums for any field with a known finite set of values :: this eliminates hallucinated alternatives. Use descriptions in schema fields :: the model reads them as instructions. Mark fields as required only if truly mandatory; nullable fields with clear labels ("null if not present") produce better outputs than forcing fabrication.

3.2.3

Function Calling

Function calling (OpenAI) / Tool use (Anthropic) lets the model decide when and how to invoke an external function :: passing structured arguments it extracts from the conversation. This is the foundation of agentic AI.

FHow Function Calling Works

You provide a list of function definitions with JSON Schema parameter specs. The model reads the conversation and, when appropriate, returns a tool_use block with the function name and extracted arguments. Your code executes the function and returns the result back to the model.

Function Calling :: Message Flow

5-STEP PROTOCOL
1
USER → MODEL
User message + function definitions provided in the API call
tools=[{"name": "get_weather", "description": "...", "input_schema": {...}}]
2
MODEL DECISION
Model decides a tool call is needed. Returns stop_reason: "tool_use" with arguments:
{"type": "tool_use", "name": "get_weather", "input": {"city": "San Francisco", "unit": "celsius"}}
3
YOUR CODE EXECUTES
You call the actual function with the model's arguments:
result = get_weather(city="San Francisco", unit="celsius") # → {"temp": 18, "condition": "foggy"}
4
TOOL RESULT → MODEL
Send result back to model in a tool_result message:
{"type": "tool_result", "tool_use_id": "...", "content": "{\"temp\": 18, \"condition\": \"foggy\"}"}
5
FINAL RESPONSE
Model uses the function result to generate a natural language reply:
"It's currently 18°C and foggy in San Francisco. You'll want to bring a jacket."
function_calling_anthropic.py
PYTHON 
from anthropic import Anthropic
import json

client = Anthropic()

# ── Define tools ──
TOOLS = [
    {
        "name": "search_products",
        "description": "Search the product catalogue by name, category, or price range",
        "input_schema": {
            "type": "object",
            "required": ["query"],
            "properties": {
                "query":      {"type": "string", "description": "Search query"},
                "category":  {"type": "string", "enum": ["electronics", "clothing", "books"]},
                "max_price": {"type": "number", "description": "Maximum price in USD"},
            }
        }
    },
    {
        "name": "add_to_cart",
        "description": "Add a product to the shopping cart by product ID",
        "input_schema": {
            "type": "object",
            "required": ["product_id", "quantity"],
            "properties": {
                "product_id": {"type": "string"},
                "quantity":   {"type": "integer", "minimum": 1},
            }
        }
    }
]

# ── Simulated tool implementations ──
def search_products(query, category=None, max_price=None):
    return [
        {"id": "P001", "name": "Wireless Headphones", "price": 89.99},
        {"id": "P002", "name": "Bluetooth Speaker",   "price": 49.99},
    ]

def add_to_cart(product_id, quantity):
    return {"success": True, "cart_total": 89.99 * quantity}

TOOL_MAP = {"search_products": search_products, "add_to_cart": add_to_cart}

# ── Agentic loop ──
def agent(user_message: str) -> str:
    messages = [{"role": "user", "content": user_message}]

    while True:
        response = client.messages.create(
            model="claude-sonnet-4-20250514",
            max_tokens=1024,
            tools=TOOLS,
            messages=messages
        )

        if response.stop_reason == "end_turn":
            return response.content[0].text  # done

        # Collect all tool uses from this response
        messages.append({"role": "assistant", "content": response.content})

        tool_results = []
        for block in response.content:
            if block.type == "tool_use":
                fn     = TOOL_MAP[block.name]
                result = fn(**block.input)
                tool_results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": json.dumps(result)
                })

        messages.append({"role": "user", "content": tool_results})

print(agent("Find me wireless audio gear under $100 and add the cheapest to my cart"))
3.2.4

Validation

LLMs can hallucinate field values even when the structure is correct. Multi-layer validation :: JSON parsing, schema validation, type checking, business rules :: catches different failure modes at each stage.

VValidation Layers

Layer 1 :: JSON Parse

Verify the output is valid JSON at all. Catches unclosed braces, invalid escape sequences, and trailing text. json.loads() or JSON.parse().

Layer 2 :: Schema Validate

Check all required fields present, types match, enums respected. Use jsonschema or Pydantic's model_validate().

Layer 3 :: Business Rules

Domain-specific checks: line_items sum ≈ total, date is not in the future, amounts are positive, tax_id format correct.

Layer 4 :: Retry Strategy

On validation failure, re-prompt with the error message: "Your output failed validation: [error]. Try again." Most models self-correct on the first retry.

robust_extractor.py
PYTHON 
import json
from pydantic import BaseModel, ValidationError, field_validator
from anthropic import Anthropic
from datetime import date

client = Anthropic()

class InvoiceExtract(BaseModel):
    invoice_number: str
    invoice_date:   str
    total_amount:   float
    currency:       str = "USD"
    vendor_name:    str
    line_items_count: int

    @field_validator("total_amount")
    @classmethod
    def total_must_be_positive(cls, v):
        if v <= 0:
            raise ValueError("total_amount must be positive")
        return v

    @field_validator("currency")
    @classmethod
    def valid_currency(cls, v):
        if v not in {"USD", "EUR", "GBP", "JPY", "CAD", "AUD"}:
            raise ValueError(f"Unknown currency: {v}")
        return v


def extract_with_retry(text: str, max_retries: int = 3) -> InvoiceExtract:
    messages = [{"role": "user", "content": text}]
    schema   = InvoiceExtract.model_json_schema()

    for attempt in range(max_retries):
        response = client.messages.create(
            model="claude-sonnet-4-20250514",
            max_tokens=1024,
            system=f"Extract invoice data. Return ONLY JSON matching: {json.dumps(schema)}",
            messages=messages
        )
        raw = response.content[0].text.strip()

        try:
            # Layer 1: JSON parse
            data = json.loads(raw.strip("` \n").removeprefix("json"))
            # Layer 2 + 3: Pydantic validates schema + business rules
            return InvoiceExtract.model_validate(data)

        except (json.JSONDecodeError, ValidationError) as e:
            if attempt == max_retries - 1:
                raise
            # Layer 4: Re-prompt with the exact error
            messages += [
                {"role": "assistant", "content": raw},
                {"role": "user", "content": f"Validation failed: {e}. Fix and return only valid JSON."}
            ]

    raise RuntimeError("Failed after all retries")
