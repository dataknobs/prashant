The Equation at the Centre of Everything

One equation defines the entire attention mechanism. Every word in it is deliberate. We will spend this chapter unpacking each component.

Scaled Dot-Product Attention
Attention(Q, K, V)  =  softmax( QKT √dk )  ·  V
Q Query matrix
[seq_len × d_k]
"What am I looking for?"
K Key matrix
[seq_len × d_k]
"What do I offer?"
V Value matrix
[seq_len × d_v]
"What I actually give"
2.2.1

Query, Key, Value

The Q/K/V abstraction borrows from information retrieval. Think of a database: you issue a query, it matches against keys, and returns the associated values. Attention does this softly :: in continuous, differentiable math.

Each token's embedding x is projected into three separate vector spaces via learned weight matrices WQ, WK, WV. These projections are learned end-to-end via backpropagation :: the model discovers what to query, what to expose as a key, and what to carry as a value.

Q

Query

The searcher

The current token's information need. "I am token i :: what context do I need from the rest of the sequence to understand my role?" Used only on the left side of the dot product.

Q = X · WQ
WQ ∈ ℝ^(d_model × d_k)
Q ∈ ℝ^(seq × d_k)
K

Key

The index label

Every token broadcasts what it contains. A query dot-products against all keys to produce relevance scores :: how much each key position is useful to this query. High Q·K similarity → high attention weight.

K = X · WK
WK ∈ ℝ^(d_model × d_k)
K ∈ ℝ^(seq × d_k)
V

Value

The content

What a token actually contributes when attended to. The output is a weighted sum of all value vectors :: attended positions donate their V vectors in proportion to attention weight.

V = X · WV
WV ∈ ℝ^(d_model × d_v)
V ∈ ℝ^(seq × d_v)
The Key Insight: Three Roles from One Input

The same input vector x spawns all three roles via different linear projections. This means a token can ask for one type of information (Q), advertise a different type (K), and share yet another (V). Separating these three concerns is what gives attention its expressive power over simpler similarity-based lookup.

→Worked Example: "The bank by the river"

Consider the word "bank". Its Query vector asks: "am I a financial institution or a riverbank?" Its Key vector is shaped by context. Attending to "river" gives a high Q·K score, so "river"'s Value vector flows into "bank"'s output :: disambiguating the meaning.

2.2.2

Attention Score Calculation

Raw attention scores are produced by computing the dot product between every Query vector and every Key vector. The result is a full seq×seq matrix of relevance scores :: one score for every (query, key) pair.

·Step-by-Step Computation

1
Project to Q, K, V

Multiply the input embedding matrix X by three separate weight matrices to get the query, key, and value matrices.

Q = X Wq    K = X Wk    V = X Wv
X:[seq,d_model] × Wq:[d_model,d_k] → Q:[seq,d_k]
2
Compute Raw Scores QKᵀ

Matrix-multiply Q by the transpose of K. Entry [i,j] measures how much query i should attend to key j.

Scores = Q Kᵀ
[seq,d_k] × [d_k,seq] → [seq,seq]
scores[i,j] = Qᵢ · Kⱼ (dot product)
3
Scale by 1/√dₖ

Divide each score by √dₖ to prevent dot products from growing too large :: which would push softmax into saturated regions with near-zero gradients.

Scores = Scores / √dₖ
dₖ = 64 → √dₖ = 8.0
Without scaling: std(QKᵀ) ≈ √dₖ
4
Apply Mask (optional)

For decoder self-attention, set future positions to −∞ so they become 0 after softmax. This enforces causality :: token i cannot see tokens i+1, i+2, …

Scores[i,j] = -∞  if j > i
Implemented as: scores.masked_fill(mask, -1e9)
Upper triangle = −∞, lower = raw score
5
Softmax → Attention Weights

Softmax converts raw scores to a probability distribution over the sequence. Each row sums to 1.0 :: the model "allocates" 100% attention across positions.

Weights = softmax(Scores, dim=-1)
Each row: Σⱼ weights[i,j] = 1.0
High score → near-1, low score → near-0
6
Weighted Sum of Values

Multiply attention weights by the value matrix. Each output token is a weighted combination of all value vectors :: attending positions "donate" their content.

Output = Weights · V
[seq,seq] × [seq,d_v] → [seq,d_v]
= Σⱼ weights[i,j] · Vⱼ

√Why Scale by √dₖ?

This is the most commonly misunderstood detail. Let's see exactly why it's necessary.

The Vanishing Gradient Problem Without Scaling

MATHEMATICAL INTUITION
Without scaling (dₖ=64)
If q,k ~ N(0,1)
q·k = Σᵢ qᵢkᵢ  (64 terms)
Var(q·k) = dₖ = 64
Std = √64 = 8.0

scores ≈ [0.1, 0.05, 45.2, 0.3, ...]
softmax → [~0, ~0, ~1.0, ~0, ...]
→ near one-hot, gradient ≈ 0
With scaling (÷ √dₖ = 8)
scores / √dₖ = scores / 8
Var(q·k/√dₖ) = 1.0
Std = 1.0

scores ≈ [0.01, 0.005, 5.65, 0.04, ...]
softmax → [0.05, 0.03, 0.78, 0.08, ...]
→ soft distribution, gradient flows ✓
Key: Var(Σᵢ qᵢkᵢ) = Σᵢ Var(qᵢkᵢ) = dₖ    (independent unit-normal terms) Dividing by √dₖ restores unit variance → stable softmax → healthy gradients during training.

▲Causal Masking Explained

In a decoder (GPT-style model), token at position i must not attend to positions i+1, i+2, … because those tokens haven't been generated yet. The causal mask enforces this by setting those scores to −∞ before softmax.

Causal Attention Mask (4-token sequence)

LOWER TRIANGULAR
Encoder vs Decoder Masking

Encoder (BERT-style): No causal mask :: every token attends to every other token bidirectionally. Full seq×seq matrix is used. Decoder (GPT-style): Causal mask applied :: upper triangle set to −∞. Token i can only aggregate information from positions 0…i. This is what makes autoregressive generation possible and prevents "cheating" during training.

2.2.5

Why Attention Works

Attention is not just a clever trick :: it solves fundamental problems that plagued all previous NLP architectures. Each design choice corresponds to a specific limitation overcome.

01

O(1) Path Length Between Any Two Tokens

In an RNN, information flows from token 1 to token 100 through 99 sequential steps :: each a potential point of information loss. In attention, every token directly attends to every other token in a single operation. Path length = 1 regardless of sequence distance.

02

Parallel Computation Across All Positions

RNNs are inherently sequential :: token n+1 cannot be processed until token n is complete. Attention computes all Q·K dot products simultaneously via matrix multiplication :: the entire sequence is processed in a single GPU-friendly operation. This unlocks the scale that makes LLMs possible.

03

Dynamic, Content-Dependent Routing

A CNN uses fixed spatial filters :: position 5 is always processed with the same kernel regardless of content. Attention weights are computed from the content itself (Q·K). The same word in different contexts routes information differently. "bank" in different sentences attends to completely different tokens.

04

Soft, Differentiable Retrieval

Attention is a weighted average :: a soft, differentiable version of a database lookup. Every value contributes (softly) to every output. Gradients flow through the weights back to both Q and K projections, allowing the model to learn what to attend to end-to-end from supervision signal alone.

05

Multi-Head Specialisation

With h attention heads, the model can simultaneously attend to h different types of information. Empirically, heads specialise: one tracks subject-verb agreement, another tracks coreference chains, another tracks sentence boundaries. This representational richness is impossible in single-vector recurrent states.

06

Interpretability Through Weights

Attention weights are human-readable. Unlike the opaque hidden states of RNNs, you can inspect the [seq×seq] weight matrix and understand which tokens influenced each output. BertViz, TransformerLens, and similar tools exploit this transparency for mechanistic interpretability research.

Attention is Not Perfect

Attention has one critical weakness: quadratic cost. Computing Q·Kᵀ requires O(n²) operations where n is sequence length. For n=128K tokens (Claude 3.5), that's ~16 billion score computations per layer per head. This is why sparse attention, linear attention, and state space models (Mamba) are active research areas :: they try to maintain the benefits of attention while reducing the quadratic bottleneck.

2.2.6

Hands-on: Implement Attention Manually

Two complete implementations :: first in pure NumPy to see every operation clearly, then in PyTorch with autograd support. Both produce identical outputs.

1Pure NumPy :: Every Step Explicit

attention_numpy.py
NUMPY 
import numpy as np

def softmax(x: np.ndarray, axis: int = -1) -> np.ndarray:
    """Numerically stable softmax using the log-sum-exp trick."""
    x_max = np.max(x, axis=axis, keepdims=True)
    e_x   = np.exp(x - x_max)  # subtract max for numerical stability
    return e_x / np.sum(e_x, axis=axis, keepdims=True)


def attention(
    Q:    np.ndarray,          # [seq, d_k]
    K:    np.ndarray,          # [seq, d_k]
    V:    np.ndarray,          # [seq, d_v]
    mask: np.ndarray = None,  # [seq, seq] bool :: True = keep, False = mask
) -> tuple:
    """
    Full scaled dot-product attention, step by step.
    Returns: (output [seq, d_v], weights [seq, seq])
    """
    d_k = Q.shape[-1]

    # ── Step 1: Raw scores ──────────────────────────────────────────
    # Q: [seq, d_k] @ K.T: [d_k, seq] = scores: [seq, seq]
    scores = Q @ K.T
    print(f"[1] Raw scores (QKᵀ):\n{scores.round(3)}\n")

    # ── Step 2: Scale ───────────────────────────────────────────────
    scores = scores / np.sqrt(d_k)
    print(f"[2] Scaled scores (÷√{d_k}={np.sqrt(d_k):.2f}):\n{scores.round(3)}\n")

    # ── Step 3: Masking ─────────────────────────────────────────────
    if mask is not None:
        scores = np.where(mask, scores, -1e9)
        print(f"[3] Masked scores:\n{scores.round(3)}\n")

    # ── Step 4: Softmax → weights ───────────────────────────────────
    weights = softmax(scores, axis=-1)
    print(f"[4] Attention weights (softmax):\n{weights.round(4)}")
    print(f"    Row sums: {weights.sum(axis=-1).round(4)}  ← all 1.0 ✓\n")

    # ── Step 5: Weighted sum of values ──────────────────────────────
    # weights: [seq, seq] @ V: [seq, d_v] = output: [seq, d_v]
    output = weights @ V
    print(f"[5] Output (weights · V):\n{output.round(4)}\n")

    return output, weights


# ── Concrete example: 4 tokens, d_k=4, d_v=4 ──
np.random.seed(42)
seq_len, d_k, d_v = 4, 4, 4

# Simulate embedding → Q,K,V projection
X  = np.random.randn(seq_len, 8)    # [4, 8] input embeddings
Wq = np.random.randn(8, d_k) * 0.3  # [8, 4]
Wk = np.random.randn(8, d_k) * 0.3  # [8, 4]
Wv = np.random.randn(8, d_v) * 0.3  # [8, 4]

Q, K, V = X @ Wq, X @ Wk, X @ Wv

# ── Bidirectional (encoder-style) ──
print("=== BIDIRECTIONAL (ENCODER) ===")
out_bi, w_bi = attention(Q, K, V)

# ── Causal (decoder-style) ──
print("=== CAUSAL MASKED (DECODER) ===")
causal_mask = np.tril(np.ones((seq_len, seq_len), dtype=bool))
out_causal, w_causal = attention(Q, K, V, mask=causal_mask)

# Verify: first row of causal output = first row of bidirectional output
# (token 0 sees the same tokens in both cases :: only itself)
print(f"Row-0 outputs equal: {np.allclose(out_bi[0], out_causal[0])}")  # → True

2PyTorch :: With Autograd & Flash Attention

attention_pytorch.py
PYTORCH 
import torch
import torch.nn.functional as F
import math

def attention_manual(
    Q: torch.Tensor,
    K: torch.Tensor,
    V: torch.Tensor,
    is_causal: bool = False,
    attn_dropout: float = 0.0,
) -> tuple[torch.Tensor, torch.Tensor]:
    """Manual attention :: mirrors F.scaled_dot_product_attention exactly."""
    d_k = Q.size(-1)
    B, H, S, _ = Q.shape

    # Raw scores: [B, H, S, S]
    scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(d_k)

    # Causal mask: upper triangle → -inf
    if is_causal:
        mask = torch.ones(S, S, device=Q.device, dtype=torch.bool).tril()
        scores = scores.masked_fill(~mask, float('-inf'))

    weights = F.softmax(scores, dim=-1)

    if attn_dropout > 0:
        weights = F.dropout(weights, p=attn_dropout)

    output = torch.matmul(weights, V)
    return output, weights


# ── Compare manual vs PyTorch 2.0 F.scaled_dot_product_attention ──
B, H, S, D = 2, 4, 16, 64
torch.manual_seed(0)
Q = torch.randn(B, H, S, D, requires_grad=True)
K = torch.randn(B, H, S, D, requires_grad=True)
V = torch.randn(B, H, S, D, requires_grad=True)

# Manual implementation
out_manual, weights = attention_manual(Q, K, V, is_causal=True)

# PyTorch 2.0 built-in (uses Flash Attention 2 when available)
out_torch = F.scaled_dot_product_attention(Q, K, V, is_causal=True)

print(f"Max diff: {(out_manual - out_torch).abs().max().item():.2e}")  # ~1e-6 (float32)
print(f"Outputs match: {torch.allclose(out_manual, out_torch, atol=1e-5)}")  # True ✓

# ── Gradient flow through attention ──
loss = out_manual.mean()
loss.backward()

print(f"\nQ.grad shape: {Q.grad.shape}")   # [2, 4, 16, 64]
print(f"K.grad norm:  {K.grad.norm():.4f}")  # non-zero :: gradients flow ✓
print(f"V.grad norm:  {V.grad.norm():.4f}")

# ── Visualise attention weights for one head ──
import matplotlib.pyplot as plt

fig, axes = plt.subplots(1, 4, figsize=(14, 4))
for h in range(4):
    w = weights[0, h].detach().numpy()  # [S, S]
    axes[h].imshow(w, cmap='Greens', vmin=0, vmax=1)
    axes[h].set_title(f"Head {h+1}", fontsize=10)
    axes[h].axis('off')

plt.suptitle("Attention weight matrices per head (causal masked)")
plt.tight_layout()
plt.savefig("attention_heads.png", dpi=150)
plt.show()

3Attention Complexity Analysis

OperationTime ComplexitySpace ComplexityBottleneck?
Q, K, V projectionsO(n · d²)O(n · d)No :: linear in sequence
QKᵀ dot productO(n² · d)O(n²)Yes :: quadratic in n
Softmax (per row)O(n²)O(n²)Yes :: must store full matrix
Weights · VO(n² · d)O(n · d)Yes :: quadratic matmul
TotalO(n² · d)O(n² + nd)n=128K → 16B ops/layer
Flash Attention: Making Quadratic Bearable

Flash Attention (Dao et al. 2022) doesn't reduce the mathematical complexity :: it's still O(n²) in FLOPs. But it restructures the computation to use GPU SRAM (fast) rather than HBM (slow memory) by tiling the QKᵀ computation into blocks. This reduces memory IO from O(n²) to O(n), achieving 2–4× wall-clock speedup and enabling contexts of 128K+ tokens. Flash Attention 2 & 3 are now standard in all major LLM implementations.
