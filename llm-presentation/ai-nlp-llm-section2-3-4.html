Tokenization

2.3.1

Byte Pair Encoding (BPE)

BPE is the dominant tokenization algorithm powering GPT-2, GPT-3, GPT-4, Llama, and most modern LLMs. It strikes the optimal balance between vocabulary size and sequence length through a simple, data-driven merge process.

BThe Algorithm

BPE starts with a character-level vocabulary and iteratively merges the most frequent adjacent pair of symbols. After k merges, you have a vocabulary of k plus the base character set. The training corpus determines which merges happen first :: common subwords get merged early, rare patterns stay split.

The BPE merge process is run offline on a training corpus. The resulting merge rules and vocabulary are then saved and used at inference time :: the tokenizer doesn't re-learn, it just applies stored rules in order.

bpe_from_scratch.py
PYTHON 
from collections import Counter, defaultdict
from typing import Dict, List, Tuple

def get_vocab(corpus: List[str]) -> Dict[str, int]:
    """Build initial character-level vocabulary with end-of-word marker."""
    vocab = Counter()
    for word in corpus:
        # Represent each word as space-separated characters + end marker
        chars = ' '.join(list(word)) + ' </w>'
        vocab[chars] += 1
    return dict(vocab)

def get_pairs(vocab: Dict) -> Dict[Tuple, int]:
    """Count all adjacent symbol pairs across the vocabulary."""
    pairs = Counter()
    for word, freq in vocab.items():
        symbols = word.split()
        for i in range(len(symbols) - 1):
            pairs[(symbols[i], symbols[i+1])] += freq
    return pairs

def merge_vocab(pair: Tuple, vocab: Dict) -> Dict:
    """Merge all instances of a pair into a single symbol."""
    import re
    pattern = re.compile(r'(?<!\S)' + re.escape(' '.join(pair)) + r'(?!\S)')
    return {pattern.sub(''.join(pair), word): freq for word, freq in vocab.items()}

def train_bpe(corpus: List[str], num_merges: int = 10) -> List[Tuple]:
    """Train BPE and return the list of merge rules."""
    vocab  = get_vocab(corpus)
    merges = []
    for i in range(num_merges):
        pairs  = get_pairs(vocab)
        if not pairs: break
        best   = max(pairs, key=pairs.get)
        vocab  = merge_vocab(best, vocab)
        merges.append(best)
        print(f"Merge {i+1:2d}: {best[0]!r} + {best[1]!r} → {best[0]+best[1]!r}  (freq={pairs[best]})")
    return merges

# ── Train on a small corpus ──
corpus = ["lower", "lowest", "newer", "wider", "new", "wide"]
merges = train_bpe(corpus, num_merges=8)

# Output:
# Merge  1: 'e' + 'r' → 'er'  (freq=4)
# Merge  2: 'er' + '</w>' → 'er</w>'  (freq=4)  ← word-final
# Merge  3: 'l' + 'o' → 'lo'  (freq=2)
# Merge  4: 'lo' + 'w' → 'low'  (freq=2)
# …
2.3.2

SentencePiece

Google's SentencePiece treats the input as a raw byte stream :: no pre-tokenization on spaces. This makes it language-agnostic and ideal for multilingual models like T5, mT5, and LLaMA.

Unlike BPE implementations that require whitespace-split words as input, SentencePiece operates directly on Unicode code points. It supports two algorithms: BPE and Unigram Language Model (ULM). The key difference from standard BPE: spaces are treated as ordinary characters (represented as a special character ▁), allowing the model to see word boundaries without hard-coding them.

The Unigram LM Algorithm (SentencePiece alternative)

Instead of greedily merging pairs, Unigram LM starts with a large candidate vocabulary and iteratively removes tokens that contribute least to the corpus likelihood. The final vocabulary is the set of tokens that maximise the probability of the training data. This is more principled than greedy BPE but computationally heavier.

2.3.3

WordPiece

Developed at Google for BERT, WordPiece is similar to BPE but selects merges based on maximising the language model likelihood rather than raw frequency. It also uses a ## prefix to mark subword continuations.

WordPiece splits unknown words into the longest matching subwords from its vocabulary. The ## prefix indicates that a subword is a continuation (not word-initial). For example, "unaffable" might tokenize as un ##aff ##able.

Tokenizer Comparison :: Same Text, Three Models

SIDE BY SIDE
Merge Strategy Differences

BPE: merge pair with highest frequency count. WordPiece: merge pair that maximises P(corpus | vocabulary) :: i.e., prefer merges that most improve the language model score, not just raw frequency. In practice the two produce very similar vocabularies for large corpora, but WordPiece is marginally more principled.

2.3.5

Why Tokenization Matters

Tokenization is not a boring preprocessing step. It directly determines cost, capability limits, failure modes, and even what tasks an LLM can solve.

$

Cost & Latency

API pricing is per token. Non-English text, code, and rare words use more tokens per character → higher cost. Japanese can cost 3× more than equivalent English.

⚠

Failure Modes

"Count letters in strawberry" fails because the model sees strawberry :: not individual characters. Spelling, arithmetic, and string reversal are harder when tokens span multiple characters.

🌐

Multilingual Equity

Underrepresented languages tokenize into more tokens per word, consuming more context window and costing more. This is a form of implicit bias baked into the vocabulary construction process.

↔

Context Window Usage

A 128K token context sounds large, but a Chinese novel may use 3× more tokens than the same story in English :: effectively giving non-English speakers a smaller effective context window.

Embeddings

2.4.1

Semantic Vector Representations

An embedding is a dense, fixed-dimensional numerical vector that encodes the meaning of text. The key property: semantically similar texts have numerically similar vectors :: closeness in vector space corresponds to closeness in meaning.

VFrom Sparse to Dense

Early NLP represented words as one-hot vectors :: a vocabulary-sized vector with a single 1. "cat" and "kitten" were completely orthogonal. Embeddings compress this into a dense representation where similar words cluster together.

2D Embedding Space :: Word Clusters

INTERACTIVE
Hover over a word to see its nearest neighbours

DWhat Gets Encoded?

Modern sentence embeddings (e.g. from text-embedding-3-large or all-MiniLM-L6-v2) encode far more than simple word co-occurrence. They capture:

Semantics

"dog" ≈ "canine" ≈ "puppy". Synonyms and paraphrases cluster together regardless of surface form.

Intent

"How do I reset my password?" ≈ "Forgot login credentials" :: same intent, zero word overlap. Critical for search.

Context

Contextual embeddings (BERT/GPT) give the same word different vectors in different contexts. "bank" (river) ≠ "bank" (finance).

2.4.2

Cosine Similarity

The standard metric for embedding similarity. Cosine similarity measures the angle between two vectors :: ignoring magnitude, focusing purely on direction. Two texts pointing in the same direction in embedding space are semantically similar.

Cosine Similarity Formula
cos(θ) = A · B |A|   |B| = Σᵢ AᵢBᵢ √(Σᵢ Aᵢ²)   √(Σᵢ Bᵢ²)
A · B Dot product
Σᵢ AᵢBᵢ
"Shared direction"
|A||B| Product of magnitudes
Normalises for length
Range: [-1, +1]
cos θ 1.0 = identical direction
0.0 = orthogonal (unrelated)
-1.0 = opposite
Why Not Euclidean Distance?

Euclidean distance (L2) is sensitive to magnitude :: a longer document embedding might score as "far" from a short one even if they discuss the same topic. Cosine similarity normalises this away, measuring only the angular relationship. For normalized embeddings (unit vectors), cosine similarity = dot product, making it extremely fast to compute on GPUs.

Hands-on: Generate Embeddings & Semantic Search

Three exercises: generating embeddings with the API, implementing cosine similarity from scratch, and building a complete semantic search engine in under 50 lines.

1Generate Embeddings with OpenAI

generate_embeddings.py
PYTHON 
from openai import OpenAI
import numpy as np

client = OpenAI()

def embed(texts: list[str], model="text-embedding-3-small") -> np.ndarray:
    """Embed a list of texts, return [N, dim] numpy array."""
    resp = client.embeddings.create(input=texts, model=model)
    return np.array([d.embedding for d in resp.data])

def cosine_similarity(a: np.ndarray, b: np.ndarray) -> float:
    """Cosine similarity between two vectors or batches."""
    a_norm = a / (np.linalg.norm(a, axis=-1, keepdims=True) + 1e-10)
    b_norm = b / (np.linalg.norm(b, axis=-1, keepdims=True) + 1e-10)
    return (a_norm @ b_norm.T).squeeze()

# ── Basic usage ──
sentences = [
    "The dog barked loudly.",
    "A canine made a loud noise.",     # semantic synonym
    "The stock market dropped sharply.", # unrelated
    "The puppy yelped at the thunder.",  # related to dog
]

embeddings = embed(sentences)
print(f"Shape: {embeddings.shape}")  # (4, 1536)

for i, s1 in enumerate(sentences):
    for j, s2 in enumerate(sentences[i+1:], i+1):
        sim = cosine_similarity(embeddings[i], embeddings[j])
        print(f"{i}↔{j}: {sim:.4f}  |  {s1[:30]}…  ↔  {s2[:30]}…")

# 0↔1: 0.8923  The dog barked…   ↔  A canine made…    ← HIGH (synonyms)
# 0↔2: 0.1247  The dog barked…   ↔  The stock market…  ← LOW (unrelated)
# 0↔3: 0.7841  The dog barked…   ↔  The puppy yelped… ← HIGH (same topic)
# 1↔2: 0.0893  A canine made…    ↔  The stock market…  ← VERY LOW
# 1↔3: 0.7643  A canine made…    ↔  The puppy yelped…  ← HIGH

2Complete Semantic Search Engine

semantic_search.py
PYTHON 
import numpy as np
from openai import OpenAI
from dataclasses import dataclass

client = OpenAI()

@dataclass
class SearchResult:
    text:  str
    score: float
    rank:  int

class SemanticSearch:
    """Simple in-memory semantic search engine."""

    def __init__(self, model: str = "text-embedding-3-small"):
        self.model      = model
        self.documents  = []
        self.embeddings = None

    def _embed(self, texts: list) -> np.ndarray:
        resp = client.embeddings.create(input=texts, model=self.model)
        vecs = np.array([d.embedding for d in resp.data], dtype=np.float32)
        return vecs / np.linalg.norm(vecs, axis=1, keepdims=True)  # L2-normalise

    def index(self, documents: list[str]):
        """Embed and store documents."""
        self.documents  = documents
        self.embeddings = self._embed(documents)
        print(f"Indexed {len(documents)} documents. Shape: {self.embeddings.shape}")

    def search(self, query: str, top_k: int = 5) -> list[SearchResult]:
        """Find top_k most similar documents to query."""
        q_emb  = self._embed([query])           # [1, dim]
        scores = (self.embeddings @ q_emb.T).squeeze()  # dot = cosine (unit vecs)
        top_k_idx = np.argsort(scores)[::-1][:top_k]
        return [
            SearchResult(text=self.documents[i], score=float(scores[i]), rank=r+1)
            for r, i in enumerate(top_k_idx)
        ]


# ── Demo ──
engine = SemanticSearch()
engine.index([
    "How to reset a forgotten password",
    "What is machine learning?",
    "Python tutorial for beginners",
    "Best restaurants in San Francisco",
    "Understanding transformer architecture",
    "I cannot log in to my account",    # semantically = password reset
    "Introduction to neural networks",
    "Top dining spots near the Golden Gate",
])

for result in engine.search("I forgot my login credentials", top_k=3):
    print(f"#{result.rank} ({result.score:.4f}): {result.text}")

# #1 (0.9241): How to reset a forgotten password   ← correct ✓
# #2 (0.8876): I cannot log in to my account        ← correct ✓
# #3 (0.3124): What is machine learning?             ← unrelated ✓
