1.3.1

Definition of a Large Language Model

Strip away the hype and an LLM is a precisely defined mathematical object: a probability distribution over sequences of tokens, parameterised by a neural network trained to predict the next token.

A Large Language Model is a deep neural network :: almost always a Transformer :: that has been trained on a massive text corpus to model the probability distribution over language. Given a sequence of tokens, it assigns a probability to every possible next token in its vocabulary.

Three words matter in the name:

Adjective

Large

Billions to trillions of trainable parameters. Scale is not just a property :: it's what produces emergent capabilities not seen in smaller models.

GPT-2: 1.5B params
GPT-3: 175B params
GPT-4: ~1T (est.)
Noun 1

Language

Trained on human language :: web text, books, code, scientific papers. The model learns statistical patterns in how humans write and reason.

Training data: 1T–15T tokens
≈ millions of books
Noun 2

Model

A mathematical function with learned parameters. Not a database or search engine :: it generates novel text by sampling from a learned probability distribution.

P(xₙ | x₁, x₂, …, xₙ₋₁)
= softmax(W · h)
175B Parameters in GPT-3 Trained on 300B tokens
100K Vocabulary size (GPT-4) Tokens, not words
2M Max context (Gemini 1.5) Tokens in one call
1.3.2

Tokens and Tokenization

LLMs don't process characters or words :: they process tokens. Understanding tokenization is fundamental to using LLMs effectively and understanding their costs, limits, and quirks.

TWhat is a Token?

A token is the atomic unit of text that an LLM processes. Tokens are not words. They are subword units produced by a tokenization algorithm :: usually Byte-Pair Encoding (BPE) :: that balances vocabulary size against sequence length.

Rules of thumb: 1 token ≈ 4 characters ≈ ¾ of a word in English. Code, rare words, and non-English text tokenize less efficiently (more tokens per character).

Example: GPT-style tokenization of a sentence

Hello, world! I am learning about Large Language Models.
Each coloured unit = 1 token. Hover to see token ID. Spaces are often merged with the following word.

BByte-Pair Encoding (BPE)

BPE is the dominant tokenization algorithm for LLMs. It starts with individual characters and iteratively merges the most frequent adjacent pair into a new token :: until the vocabulary reaches a target size (typically 32K–100K).

BPE: Step-by-step merge

ALGORITHM
START l o w e r → 5 tokens
MERGE 1 lo w e r "l"+"o" most frequent → merge
MERGE 2 low e r "lo"+"w" → merge
MERGE 3 low er "e"+"r" → merge
RESULT lower → 1 token (in vocab)
Unknown word "lowers" → [lower][s] = 2 tokens  |  "lowest" → [low][est] = 2 tokens
BPE gracefully handles unseen words by breaking into known subword units.
Tokenization Quirks That Affect Prompting

LLMs process tokens, not characters :: so "Count the letters in 'strawberry'" is genuinely hard: the model sees [straw][berry], not individual letters. Arithmetic, spelling, and string manipulation are harder for tokenized models than for humans. Knowing this helps you design better prompts and understand failure modes.

1.3.3

Training Objectives

LLMs are trained in multiple phases :: each with a different objective. Understanding these phases explains why LLMs behave differently from raw language models, and why RLHF-trained models are helpful assistants rather than internet-text imitators.

  1. Phase 1 :: Self-supervised Pretraining (Causal LM)

    The model is trained on trillions of tokens from the internet, books, and code. Objective: predict the next token given all previous tokens. No human labels required :: the text itself provides supervision. This builds broad world knowledge and language understanding.

  2. Phase 2 :: Supervised Fine-tuning (SFT)

    Human annotators write high-quality prompt–response pairs. The model is fine-tuned to produce outputs that look like those demonstrations. This teaches the format of being a helpful assistant.

  3. Phase 3 :: Reward Modeling

    For a given prompt, the model generates multiple responses. Human raters rank them. A separate reward model is trained to predict human preference scores :: this becomes the signal for Phase 4.

  4. Phase 4 :: RLHF (Reinforcement Learning from Human Feedback)

    The SFT model is further fine-tuned using Proximal Policy Optimisation (PPO), maximising the reward model's score. This aligns the model to be helpful, harmless, and honest :: producing the ChatGPT/Claude-style assistant behaviour.

Why This Matters

A base LLM (post-Phase 1) will complete your text in the style of the internet :: often producing plausible-sounding but unhelpful or harmful content. The RLHF pipeline is what transforms a raw language model into a useful AI assistant. When you use Claude or ChatGPT, you're using a heavily RLHF-trained model, not a raw pretrained one.

1.3.4

Next-Token Prediction

Everything an LLM does :: answering questions, writing code, reasoning through problems :: emerges from one deceptively simple objective: predict the next token.

PThe Core Mechanism

At inference time, an LLM takes a sequence of tokens (the prompt) and outputs a probability distribution over its entire vocabulary (~100K tokens). The highest-probability token is the most likely next word :: but we don't always pick the top one (see Temperature, below).

This process repeats autoregressively: the chosen token is appended to the context, and the model predicts the next one. This continues until a stop token or max length is reached.

Profound Implication

Next-token prediction seems narrow but requires vast world knowledge. To predict "Paris" after "The capital of France is", the model must have learned geography. To complete Python code correctly, it must understand programming. The training objective forces the model to implicitly learn virtually everything needed to complete human-written text.

1.3.5

Emergent Capabilities

As models scale beyond certain parameter counts, qualitatively new capabilities appear that were absent in smaller models :: not gradually, but sharply. This phenomenon is called emergence.

Emergent capabilities are abilities that are not present in smaller models and not explicitly trained for. They arise spontaneously from scale. The canonical paper is "Emergent Abilities of Large Language Models" (Wei et al., 2022), which documented dozens of such capabilities with sharp phase transitions.

~100B+ params

Chain-of-Thought Reasoning

When prompted to "think step by step," large models produce multi-step reasoning that dramatically improves accuracy on maths, logic, and science problems. Absent in models under ~50B parameters.

Appears sharply at ~62B+ parameters
~7B+ params

In-Context Learning

Learning a new task from a handful of examples provided in the prompt alone :: with no gradient updates. The model generalises from 3–5 examples to unseen inputs. Unprecedented in prior ML paradigms.

Improves sharply with scale
~50B+ params

Code Generation & Execution

Writing syntactically correct, functionally accurate code in dozens of programming languages. Includes debugging, explaining code, and generating unit tests :: without explicit code-generation training.

Quality jumps sharply at scale
~100B+ params

Theory of Mind

The ability to reason about other agents' beliefs, intentions, and knowledge states :: a core aspect of human social cognition. GPT-4 passes Sally-Anne false-belief tasks that smaller models fail.

Near-absent below 100B params
~30B+ params

Multilingual Zero-shot Transfer

Solving tasks in languages with little or no training data for that task, by transferring knowledge from better-represented languages. A model trained mostly in English can answer questions in Swahili.

Improves with scale & data diversity
~10B+ params

Instruction Following

Understanding and executing complex multi-step instructions without explicit examples :: including negations, conditionals, and style constraints. "Write a haiku about photosynthesis but avoid scientific terms."

Dramatically better at scale + RLHF
The Debate: Is Emergence Real?

A 2023 paper (Schaeffer et al.) argued emergence is partly an artifact of non-linear metrics :: smooth capability gains appear discontinuous because the metrics used are all-or-nothing (pass/fail on a benchmark). Whether true phase transitions exist or are metric artifacts is an active research debate. In practice, qualitative capability jumps with scale are real and reproducible.

1.3.6

Scaling Laws

One of the most striking discoveries in deep learning: LLM performance scales predictably as a power law with compute, parameters, and data :: enabling researchers to forecast model quality before training.

SThe Kaplan et al. Laws (2020)

OpenAI's 2020 paper ("Scaling Laws for Neural Language Models") showed that language model loss follows clean power laws as a function of three variables:

Power Law: Loss vs Scale

LOG-LOG SCALE

CChinchilla Laws (2022)

DeepMind's "Chinchilla" paper (Hoffmann et al., 2022) revised Kaplan's findings: for a given compute budget, you should train a smaller model on more data. The optimal ratio is roughly 20 tokens of training data per parameter.

ModelParametersTraining TokensChinchilla-optimal?
GPT-3175B300B⚠ Under-trained (~1.7 tok/param)
Chinchilla70B1.4T✓ Optimal (20 tok/param)
Llama 2 (7B)7B2T✓ Over-trained for inference
Llama 3 (8B)8B15T✓ Deliberately over-trained
Practical Takeaway

The Chinchilla result shifted the industry from chasing parameter counts to training smaller models on far more data. A well-trained 7B model often outperforms a poorly-trained 70B model. Scale matters :: but the ratio of parameters to tokens matters just as much.

1.3.7

Key Concepts

Five essential parameters and concepts that govern every LLM inference call. Mastering these makes the difference between mediocre and excellent LLM usage.

PParameters & Inference

Foundation

Parameters

The learned weights of the neural network :: billions of floating-point numbers that encode the model's knowledge. Set during training, frozen at inference. More parameters ≈ more capacity to store knowledge and learn patterns.

GPT-3: 175,181,291,520 parameters
Each = 16-bit float = 2 bytes
→ ~350GB to load in memory
Inference

Inference

Running a trained model to produce outputs :: i.e. generating text from a prompt. During inference, parameters are frozen; no learning occurs. Inference cost scales with context length squared (attention) and model size linearly.

Inference cost ∝ N_params × L²
where L = sequence length
(why long contexts cost more)
Context

Context Window

The maximum number of tokens an LLM can process in a single call :: both input (prompt) and output (response) combined. Everything outside the context window is invisible to the model.

GPT-4o: 128K tokens (~300 pages)
Claude 3.5: 200K tokens (~500 pages)
Gemini 1.5: 1–2M tokens
Memory

Statelessness

LLMs have no memory between API calls. Each call is independent. What looks like "conversation memory" in ChatGPT is actually the entire conversation history being re-sent as context on every turn.

Conversation token cost =
Σ all previous messages
+ current prompt + response

TTemperature & Sampling

When the model produces a probability distribution over the next token, how do we pick from it? Temperature and sampling strategies control the randomness and creativity of outputs.

Greedy
temp=0		 Always pick the highest-probability token. Deterministic, reproducible. Factual Q&A, classification, structured extraction where you want consistency
Temperature Sampling
temp=0.1–1.0		 Divide logits by temperature before softmax. Low T → sharper; High T → flatter distribution. General use. Low (0.2) for code/facts, medium (0.7) for chat, high (1.0) for creative writing
Top-k Sampling
k=40–100		 Restrict sampling to the top-k most probable tokens. Zero probability to the rest. Prevents extremely unlikely tokens while maintaining diversity
Top-p (Nucleus)
p=0.9–0.95		 Sample from the smallest set of tokens whose probabilities sum to ≥ p. Dynamic k. Most common in production; adapts to distribution shape. OpenAI default: top_p=1
Beam Search Maintain k candidate sequences simultaneously; pick the one with highest total log-prob. Translation, summarisation where you want the globally best sequence (not generation)

Hands-on: Token Counting & Context Experiments

Two practical exercises: counting tokens accurately (critical for cost management and prompt engineering), and experimenting with context length to see how LLMs use and lose context.

1Token Counting with tiktoken

token_counting.py
PYTHON 
import tiktoken

# tiktoken is OpenAI's tokenizer library :: free, offline, exact counts
# pip install tiktoken

# ── Load the tokenizer for a specific model ──
enc_gpt4  = tiktoken.encoding_for_model("gpt-4o")    # cl100k_base
enc_gpt35 = tiktoken.encoding_for_model("gpt-3.5-turbo") # same encoding

def count_tokens(text: str, model: str = "gpt-4o") -> dict:
    enc    = tiktoken.encoding_for_model(model)
    tokens = enc.encode(text)
    return {
        "n_tokens":  len(tokens),
        "n_chars":   len(text),
        "ratio":     round(len(text) / len(tokens), 2),
        "token_ids": tokens[:10],  # first 10 IDs
        "decoded":   [enc.decode([t]) for t in tokens[:10]]
    }

# ── Examples ──
texts = {
    "Simple English":  "The quick brown fox jumps over the lazy dog.",
    "Technical":       "Transformers use self-attention and positional encoding.",
    "Code":            "def fibonacci(n): return n if n < 2 else fibonacci(n-1)+fibonacci(n-2)",
    "Japanese":        "大規模言語モデルは自然言語処理を変革しました。",
    "Long word":       "supercalifragilisticexpialidocious",
}

for label, text in texts.items():
    result = count_tokens(text)
    print(f"{label}:")
    print(f"  Tokens: {result['n_tokens']} | Chars: {result['n_chars']} | Ratio: {result['ratio']} chars/tok")
    print(f"  First tokens: {result['decoded']}\n")

# Output:
# Simple English: Tokens: 9  | Chars: 44 | Ratio: 4.89 chars/tok
# Technical:      Tokens: 9  | Chars: 55 | Ratio: 6.11 chars/tok
# Code:           Tokens: 22 | Chars: 71 | Ratio: 3.23 chars/tok
# Japanese:       Tokens: 22 | Chars: 22 | Ratio: 1.00 chars/tok  ← expensive!
# Long word:      Tokens: 7  | Chars: 34 | Ratio: 4.86 chars/tok

# ── Count tokens for an entire chat conversation ──
def count_chat_tokens(messages: list, model: str = "gpt-4o") -> int:
    enc   = tiktoken.encoding_for_model(model)
    total = 0
    for msg in messages:
        total += 4  # every message has 4 overhead tokens
        for key, value in msg.items():
            total += len(enc.encode(value))
    total += 2  # priming tokens for reply
    return total

2Context Length Experiments

context_experiments.py
PYTHON 
from openai import OpenAI
import tiktoken

client = OpenAI()
enc    = tiktoken.encoding_for_model("gpt-4o")

# ── Experiment 1: "Lost in the Middle" ──
# LLMs attend better to beginning and end of context than the middle.
# Test this by hiding a key fact at different positions.

def build_context(secret_position: str = "middle") -> str:
    padding = "The sky is blue. " * 100  # ~300 tokens of filler
    secret  = "The magic number is 42891."
    if   secret_position == "start":  return secret + padding
    elif secret_position == "middle": return padding[:len(padding)//2] + secret + padding[len(padding)//2:]
    elif secret_position == "end":    return padding + secret

for pos in ["start", "middle", "end"]:
    context  = build_context(pos)
    n_tokens = len(enc.encode(context))
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": "Answer with ONLY the number, nothing else."},
            {"role": "user",   "content": f"{context}\n\nWhat is the magic number?"}
        ],
        max_tokens=10,
        temperature=0
    )
    answer = response.choices[0].message.content.strip()
    print(f"Position: {pos:8s} | Tokens: {n_tokens:4d} | Answer: {answer}")

# Typical result:
# Position: start  | Tokens:  324 | Answer: 42891  ✓  (strong primacy effect)
# Position: middle | Tokens:  324 | Answer: 10000  ✗  (lost in the middle!)
# Position: end    | Tokens:  324 | Answer: 42891  ✓  (strong recency effect)
#
# Key finding: critical info belongs at START or END of your prompt, never buried.

# ── Experiment 2: Measure attention by position ──
def test_recall_at_length(n_filler_tokens: int) -> bool:
    filler  = "The weather is nice today. " * (n_filler_tokens // 6)
    prompt  = f"Remember: XKCD2847. {filler} What was the code I asked you to remember?"
    resp    = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0, max_tokens=20
    )
    return "XKCD2847" in resp.choices[0].message.content

for length in [100, 500, 2000, 10000, 50000]:
    recalled = test_recall_at_length(length)
    print(f"Filler tokens: {length:6d} | Recalled: {recalled}")
The "Lost in the Middle" Finding

Liu et al. (2023) showed that LLMs attend most strongly to tokens at the beginning and end of their context window :: information buried in the middle is recalled significantly less well. This has direct practical implications: put your most important instructions at the start or end of your prompt, never in the middle of a long document.
