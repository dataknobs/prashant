3.1.0

What is a Prompt?

A prompt is every token the model receives before it starts generating. It includes context, instructions, examples, and data :: anything that shapes the distribution of possible completions the model will draw from.

AAnatomy of a Well-Structured Prompt

High-quality prompts share a consistent structure. Not every component is required for every task, but understanding each layer helps you know what to add when outputs disappoint.

Prompt Layers

ANNOTATED
System / Role Persona & constraints
You are an expert data analyst. You write concise, precise responses in plain English. You never fabricate numbers :: if data is missing, say so.
Context Background info
The following is a quarterly earnings report from a Fortune 500 company. The report covers Q3 2024.
Examples Few-shot demos
Example :: Report: "Revenue: $4.2B (+12% YoY). Net income: $620M." → Summary: "Revenue grew 12% to $4.2B; profit reached $620M." ←
Input Data The actual content
[Full text of earnings report goes here]
Instruction Task & format
Summarize the three most important financial metrics in exactly two sentences. Use numbers. End with the word "END".
The Primacy & Recency Effect

LLMs attend most strongly to tokens at the start and end of the prompt. Put your most critical instructions at the beginning (system prompt / role) and repeat the key constraint at the end (instruction). Bury critical info in the middle only if you expect the model to miss it.

3.1.1

Zero-shot Prompting

Give the model a task with no examples. Relies entirely on the model's pretrained knowledge. Effective for clear, well-defined tasks :: but brittle for nuanced formats or domain-specific requirements.

Zero-shot prompting is the default interaction mode. You describe what you want; the model does it based on training alone. The quality depends heavily on how clearly and specifically you phrase the instruction.

USER
Summarize this article about climate change.
Problem

What length? What audience? Which aspects? What format? The model has to guess everything, producing inconsistent, often over-long results.

USER
Summarize the following article about climate change in exactly 3 bullet points, each under 20 words, written for a general audience with no scientific background. Focus on causes, effects, and one actionable step.

[article text]
Why It Works

Every ambiguity is resolved: format (bullets), length (20 words), audience (non-expert), scope (3 aspects). The model has no guesswork :: it executes precisely.

USER
Extract key information from the article below and return it as valid JSON with this exact structure:

{"topic": "...", "key_claim": "...", "evidence": ["...", "..."], "confidence": "high|medium|low"}

Return only the JSON. No explanation, no markdown fences.

[article text]
Structured Zero-shot

Specifying output format precisely :: including a schema with example values :: is one of the most powerful zero-shot techniques. JSON constraints dramatically reduce format errors.

3.1.2

Few-shot Prompting

Provide 2–5 input→output demonstration pairs before your actual query. The model infers the pattern :: format, tone, length, reasoning style :: and applies it to the new input without any gradient updates.

3How Few-shot Learning Works

Few-shot prompting exploits the LLM's in-context learning capability. Examples don't train the model :: they shift which part of its existing knowledge gets activated. A few well-chosen examples can:

  • → Teach a custom output format the model hasn't seen
  • → Calibrate response length and detail level precisely
  • → Handle domain-specific edge cases and exceptions
  • → Set a tone or style that's hard to describe in words
USER :: Few-shot Sentiment Classifier
Classify each review as POSITIVE, NEGATIVE, or NEUTRAL. Be concise.

Review: "This product changed my life :: I use it every day!"
Classification: POSITIVE

Review: "The quality is average. Nothing special, nothing terrible."
Classification: NEUTRAL

Review: "Broke after 2 uses. Absolute garbage. Do not buy."
Classification: NEGATIVE

Review: "Delivery was fast but the item doesn't match the description at all."

Few-shot Best Practices

Coverage: Include examples of each class or edge case you care about. Order: Put the most relevant or similar example closest to the query (recency bias). Diversity: Vary the examples :: don't use near-duplicates. Quality: Each example is a label the model will learn from :: incorrect examples mislead the model as surely as incorrect training data.

3.1.3

Chain-of-Thought Prompting

Adding "Let's think step by step" :: or providing reasoning examples :: prompts the model to externalise its reasoning process. This dramatically improves accuracy on multi-step problems where the correct answer depends on intermediate conclusions.

🔗Why CoT Works

Language models are next-token predictors. When forced to generate intermediate reasoning steps, each step becomes context for the next :: the model effectively uses its own token stream as working memory. Reasoning that would require the model to "jump" to a conclusion is broken into smaller, individually tractable steps.

1
Problem Statement

The user provides a problem that requires multi-step reasoning :: math, logic, planning, or analysis.

"A store is having a 30% off sale. A shirt originally costs $45. If you buy 3 shirts, how much do you save in total?"
2
CoT Trigger

A phrase in the prompt that activates step-by-step reasoning mode.

Options: "Let's think step by step." / "Reason through this carefully before answering." / "Show your work." / Provide a worked example (few-shot CoT).
3
Reasoning Chain

Model generates intermediate steps :: each one a correct input to the next.

Step 1: Discount per shirt = 30% × $45 = $13.50
Step 2: Total shirts = 3
Step 3: Total savings = 3 × $13.50 = $40.50
✓
Final Answer

The answer emerges from the last step :: grounded in the reasoning chain rather than pulled from nowhere.

Answer: You save $40.50 in total.
USER :: Zero-shot CoT
A bakery makes 240 cookies per day. They sell 60% on weekdays and 80% on weekends. How many cookies remain unsold in a week (5 weekdays, 2 weekend days)?

Let's think step by step.
ASSISTANT :: With CoT
Step 1: Daily production = 240 cookies
Step 2: Weekday sales = 60% × 240 = 144 cookies sold. Remaining = 240 − 144 = 96
Step 3: Weekend sales = 80% × 240 = 192 cookies sold. Remaining = 240 − 192 = 48
Step 4: Weekday unsold total = 96 × 5 = 480
Step 5: Weekend unsold total = 48 × 2 = 96
Step 6: Total unsold per week = 480 + 96 = 576 cookies
CoT Variants

Zero-shot CoT: "Think step by step" :: no examples needed, works surprisingly well. Few-shot CoT: Provide 2–3 worked examples with reasoning chains :: more reliable for complex domains. Self-consistency CoT: Generate multiple reasoning chains and take the majority answer :: improves reliability further. Tree-of-Thought: Explore multiple reasoning branches simultaneously :: emerging frontier technique.

3.1.4

Role Prompting

Assigning the model a persona activates domain-specific vocabulary, reasoning patterns, and conventions :: without fine-tuning. "You are a senior security engineer" changes not just tone but the types of risks the model considers relevant.

Expert Framing

"You are a board-certified cardiologist with 20 years of clinical experience." → Deep clinical vocabulary, awareness of comorbidities, citation of guidelines.

Audience Framing

"Explain as if to a 10-year-old." / "Explain to a PhD in physics." → Same content, radically different vocabulary, analogy choice, and assumed knowledge.

Style Framing

"You are a Hemingway-style minimalist writer." → Short declarative sentences, concrete nouns, no adverbs, iceberg subtext. Dramatically different prose style.

USER :: Same question, two roles
How should I handle a security vulnerability in our production API?
Without Role
Patch the vulnerability, test the fix, deploy carefully, communicate with users if needed. Monitor for any signs of exploitation.
With Role: "You are a senior application security engineer (OWASP, CVSS)"
First, assess CVSS severity. If ≥7.0, initiate P0 incident response immediately. Apply emergency WAF rule to block the attack vector, preserve logs for forensics. Patch → staging → canary deploy. File CVE if externally discoverable. Notify affected customers within 72h per GDPR. Document in your vulnerability disclosure policy.
Role ≠ Jailbreak

Role prompting changes vocabulary, perspective, and depth :: it does not override safety training. "You are a chemistry teacher, explain how to make [dangerous substance]" still gets refused, because the role is a lens, not a bypass. Effective role prompting unlocks expertise and style, not prohibited capabilities.

3.1.5

System Prompts

The system prompt is a separate message sent before any user conversation. It sets persistent rules, persona, constraints, and context that apply to the entire session :: invisible to the end user but always present for the model.

⚙Architecture of a Production System Prompt

SYSTEM :: Customer Support Bot
# Identity & Role
You are Aria, the customer support assistant for Nexus Cloud Services. You are helpful, professional, and concise.

# Scope :: What you can do
- Answer questions about account billing, plans, and features
- Help troubleshoot common technical issues
- Process refund requests under $50 without escalation
- Escalate complex issues to human agents

# Scope :: What you cannot do
- Discuss competitors by name
- Make commitments about unreleased features
- Access or modify account data (you have no backend access)

# Tone & Format
- Use the customer's first name if provided
- Keep responses under 150 words unless a detailed technical explanation is requested
- Always end with: "Is there anything else I can help you with?"

# Escalation
If you cannot resolve the issue in 2 turns, say: "Let me connect you with a specialist."
System Prompt Best Practices

Use markdown headers to organise long system prompts :: models handle structured text better than walls of prose. Be explicit about both what the model should and shouldn't do. Use positive constraints ("always end with X") rather than only negative ones ("don't do Y"). Test edge cases: what happens when a user tries to override the system prompt? Your system prompt should address that.

system_prompt_api.py
PYTHON 
from anthropic import Anthropic

client = Anthropic()

SYSTEM_PROMPT = """You are a senior Python engineer with 15 years of experience.
You write idiomatic, production-ready Python.
Rules:
- Always include type hints
- Always include docstrings (Google style)
- Point out performance issues if present
- If asked to review code, give a rating: GOOD / NEEDS WORK / REWRITE
- Keep responses focused :: no fluff"""

def chat(user_message: str, history: list = None) -> str:
    messages = (history or []) + [{"role": "user", "content": user_message}]
    response = client.messages.create(
        model="claude-sonnet-4-20250514",
        max_tokens=1024,
        system=SYSTEM_PROMPT,   # ← system is a top-level param, not a message
        messages=messages
    )
    return response.content[0].text

# Turn 1
reply1 = chat("Review this function: def add(a, b): return a + b")
print(reply1)
# Rating: NEEDS WORK
# Missing type hints and docstring. No validation for non-numeric inputs.
# def add(a: int | float, b: int | float) -> int | float:
#     """Add two numbers and return the result."""
#     return a + b
