3.3.1

Prompt Testing

Gut-feel prompt writing produces inconsistent results. Systematic testing :: with a fixed test suite, clear evaluation criteria, and multiple runs :: is what separates prompt engineering from prompt guessing.

TThe Prompt Testing Cycle

Every meaningful prompt change should go through the same loop: hypothesis → variant → test suite → measure → decide. This is the same scientific method applied to LLM prompts.

Prompt Optimization Loop

PROCESS

MEvaluation Metrics

MetricHow to MeasureBest ForPitfall
Exact MatchOutput == expected stringClassification, short factual answersToo strict :: misses correct paraphrases
Substring MatchExpected string in outputExtraction, keyword presenceDoesn't check for extra unwanted content
BLEU / ROUGEN-gram overlap with referenceSummarization, translationRewards word overlap, not semantic correctness
LLM-as-JudgeSecond LLM rates outputs 1–5Open-ended quality, style, reasoningJudge bias; expensive; need rubric
Task-specificCustom function (F1, accuracy, parsed field check)Production metrics that actually matterMust define carefully; takes time to build
Latencytime.perf_counter() around API callAny production promptHigh variance :: run 5+ times, use median
Token Countresponse.usage.output_tokensCost optimisationShorter ≠ better; verify quality holds
LLM-as-Judge :: The Most Powerful Evaluator

For nuanced outputs (writing quality, reasoning quality, helpfulness), a second LLM evaluating against a detailed rubric outperforms simple string matching. Key: give the judge a rubric with anchored score descriptions, not just "rate 1–10". Ask it to output a JSON score with a reasoning field. Use GPT-4o or Claude Sonnet as judge even when evaluating cheaper models.

FWhat to Test For

Happy Path

Standard inputs where you know the correct answer. Verifies the prompt works at all for the normal case.

Edge Cases

Empty input, very long input, non-English text, ambiguous phrasing. These reveal brittleness invisible in happy-path testing.

Adversarial

Prompt injections, contradiction in context, misleading framing. Test that your prompt is robust to malicious or confusing inputs.

3.3.2

Prompt Templates

Hardcoded prompts are fragile. Prompt templates with named variables make prompts reusable, testable, version-controlled, and composable :: turning a one-off string into a production asset.

TTemplate Patterns

prompt_templates.py
PYTHON 
from string import Template
from dataclasses import dataclass
from typing import Any
import json

# ── Pattern 1: Simple f-string template ──
def classify_prompt(text: str, categories: list[str]) -> str:
    return f"""Classify the following text into exactly one category.
Categories: {', '.join(categories)}
Return only the category name, nothing else.

Text: {text}"""

# ── Pattern 2: Dataclass-based template (versioned, typed) ──
@dataclass
class SummaryTemplate:
    version:    str = "v2.1"
    max_bullets: int = 3
    audience:   str = "general"
    language:   str = "English"
    style:      str = "concise"  # concise | detailed | executive

    def render(self, document: str) -> str:
        style_guides = {
            "concise":   "Short, punchy bullets. Max 15 words each.",
            "detailed":  "Full sentences with supporting context.",
            "executive": "Business impact and recommendations only.",
        }
        return f"""Summarize the following document in {self.max_bullets} bullet points.
Audience: {self.audience}
Language: {self.language}
Style: {style_guides.get(self.style, self.style)}
Format: Use • as bullet character. No markdown.

Document:
{document}"""

# ── Pattern 3: Few-shot template with dynamic examples ──
def few_shot_prompt(
    task_description: str,
    examples: list[dict],      # [{"input": ..., "output": ...}]
    query: str,
    output_format: str = "",
) -> str:
    example_block = "\n\n".join(
        f"Input: {ex['input']}\nOutput: {ex['output']}"
        for ex in examples
    )
    fmt = f"\nReturn format: {output_format}" if output_format else ""
    return f"""{task_description}{fmt}

Examples:
{example_block}

Input: {query}
Output:"""

# ── Pattern 4: Template registry with A/B support ──
class PromptRegistry:
    def __init__(self):
        self._templates: dict[str, dict] = {}

    def register(self, name: str, template: str, version: str = "1.0", metadata: dict = None):
        self._templates[name] = {
            "template": template, "version": version,
            "metadata": metadata or {},
        }

    def render(self, name: str, **kwargs: Any) -> str:
        entry = self._templates[name]
        return Template(entry["template"]).safe_substitute(**kwargs)

    def list_versions(self, name: str) -> list:
        return [v["version"] for v in self._templates.get(name, {}).values()]

registry = PromptRegistry()
registry.register(
    name="email_classifier",
    version="2.3",
    template="""Classify the email into: $categories
Return JSON: {"category": "...", "confidence": 0.0–1.0}

Email subject: $subject
Email body: $body""",
    metadata={"task": "classification", "model": "claude-sonnet-4"}
)

prompt = registry.render(
    "email_classifier",
    categories="SALES / SUPPORT / BILLING / OTHER",
    subject="Invoice #4821 overdue",
    body="Your payment of $2,400 is 30 days past due…"
)

Guardrails

Guardrails are mechanisms that prevent LLMs from producing outputs outside acceptable boundaries :: detecting off-topic requests, harmful content, prompt injection attacks, and policy violations before they reach users.

GGuardrail Architecture

LayerWhat It CatchesImplementationCost
Input guardrailPrompt injection, off-topic queries, PII in inputClassifier prompt or regex pre-check before main LLM callLow :: fast, cheap model
System prompt hardeningRole drift, instruction override attempts"Ignore all previous instructions" resistance baked inZero :: just words
Output guardrailSensitive content, hallucinated facts, format violationsSecond LLM or rule-based check on response before servingMedium :: adds latency
Schema enforcementWrong format, missing fields, invalid valuesPydantic / JSON Schema validation + retryLow :: local check
Semantic similarityOff-topic responses that pass format checksEmbed output, compare to expected topic clusterMedium :: embedding API
guardrails.py
PYTHON 
from anthropic import Anthropic
from dataclasses import dataclass
from enum import Enum

client = Anthropic()

class GuardrailResult(Enum):
    SAFE      = "safe"
    FLAGGED   = "flagged"
    UNCERTAIN = "uncertain"

@dataclass
class GuardrailCheck:
    result:     GuardrailResult
    reason:     str
    confidence: float

def input_guardrail(user_input: str, allowed_topics: list[str]) -> GuardrailCheck:
    """Check if user input is on-topic and safe before sending to main LLM."""
    import json
    prompt = f"""Assess this user message for safety and topic relevance.
Allowed topics: {', '.join(allowed_topics)}

User message: "{user_input}"

Return JSON only:
{{"result": "safe|flagged|uncertain",
  "reason": "brief explanation",
  "confidence": 0.0-1.0,
  "detected_issues": ["list", "of", "issues", "or", "empty"]}}"""

    response = client.messages.create(
        model="claude-haiku-4-5",  # fast cheap model for guardrail
        max_tokens=256,
        messages=[{"role": "user", "content": prompt}]
    )

    try:
        data  = json.loads(response.content[0].text)
        return GuardrailCheck(
            result=GuardrailResult(data["result"]),
            reason=data["reason"],
            confidence=data["confidence"]
        )
    except:
        return GuardrailCheck(GuardrailResult.UNCERTAIN, "Parse error", 0.5)


def safe_complete(user_input: str, system: str, allowed_topics: list[str]) -> str:
    """Full pipeline with input guardrail."""
    # Step 1: Guardrail check (cheap, fast)
    check = input_guardrail(user_input, allowed_topics)

    if check.result == GuardrailResult.FLAGGED:
        return f"I can only help with: {', '.join(allowed_topics)}."

    if check.result == GuardrailResult.UNCERTAIN and check.confidence > 0.7:
        return "I'm not sure I can help with that. Could you rephrase?"

    # Step 2: Main completion (expensive, powerful)
    response = client.messages.create(
        model="claude-sonnet-4-20250514",
        max_tokens=1024,
        system=system,
        messages=[{"role": "user", "content": user_input}]
    )
    return response.content[0].text

3.3.4

Hallucination Reduction

LLMs generate plausible-sounding text whether or not they know the answer. Hallucination is a fundamental property of autoregressive generation :: but prompt design can dramatically reduce its frequency and severity.

HWhy Hallucination Happens

The model is trained to predict the most plausible next token given context. "Most plausible" is not the same as "most accurate." When the model has weak signal for a specific fact, it interpolates from its training distribution :: producing confident-sounding, coherent, but incorrect text.

TechniqueHow It WorksReduction Impact
Ground in contextProvide the source document; instruct model to cite it★★★★★ Best overall
"I don't know" permissionExplicitly say "If you don't know, say 'I don't know'"★★★★☆ High impact
Ask for citations"Cite the specific sentence from the document"★★★★☆ Forces grounding
Chain-of-thoughtStep-by-step reasoning catches mid-chain errors★★★☆☆ Helps reasoning tasks
Temperature = 0Deterministic: always picks highest-probability token★★☆☆☆ Reduces variation, not error
Self-consistencyRun N times, take majority answer★★★☆☆ Good for closed-domain QA
Confidence elicitation"Rate your confidence 1–10 and explain"★★★☆☆ Surfaces uncertainty
RAG (Retrieval)Retrieve relevant docs; model only uses retrieved content★★★★★ Gold standard for facts

# ── Technique 1: Grounded extraction with citation ──
GROUNDED_SYSTEM = """You are a document analyst.
CRITICAL RULES to prevent errors:
- Answer ONLY from the provided document
- If the answer is not in the document, say "Not found in document"
- Quote the exact sentence that supports your answer
- Never infer or extrapolate beyond what is explicitly stated"""

GROUNDED_USER = """Document:
{document}

Question: {question}

Format your response as:
Answer: [your answer]
Evidence: "[exact quote from document]"
Confidence: [high/medium/low :: based on how explicitly the document states this]"""

# ── Technique 2: Explicit uncertainty permission ──
UNCERTAIN_OK_SYSTEM = """You are a medical information assistant.
Important: You are not a doctor and should not make diagnoses.
If you are not certain about a medical fact, say "I'm not sure" or
"You should consult a doctor for this."
It is far better to express uncertainty than to give incorrect medical information."""

# ── Technique 3: Self-consistency voting ──
import asyncio
from anthropic import AsyncAnthropic
from collections import Counter

aclient = AsyncAnthropic()

async def self_consistent_answer(
    question: str, n_samples: int = 5, temperature: float = 0.7
) -> tuple[str, float]:
    """Run question N times, return majority answer + confidence."""
    tasks = [
        aclient.messages.create(
            model="claude-haiku-4-5",
            max_tokens=100,
            messages=[{"role": "user", "content": question + "\nAnswer with the key fact only."}]
        )
        for _ in range(n_samples)
    ]
    responses = await asyncio.gather(*tasks)
    answers   = [r.content[0].text.strip() for r in responses]
    majority, count = Counter(answers).most_common(1)[0]
    confidence = count / n_samples
    return majority, confidence

# Run: asyncio.run(self_consistent_answer("What year was Python created?", n_samples=5))
# → ("1991", 0.8)  :: 4 out of 5 samples agreed
3.3.5

Latency vs Quality Tradeoffs

Every prompt engineering decision lives on a frontier: more tokens and larger models improve quality but increase cost and latency. Knowing where your use case sits on this frontier determines the right strategy.

The Latency–Quality Frontier

STRATEGY MAP
Optimisation LeverLatency ImpactQuality ImpactCost Impact
Smaller model (Haiku vs Sonnet)↓↓ 3–10× faster↓ 10–30% worse↓↓ 5–20× cheaper
Remove few-shot examples↓ faster (fewer tokens)↓ variable; test it↓ fewer input tokens
Shorten system prompt↓ marginal↓ watch for format drift↓ marginal
Set max_tokens limit↓ stops early↑ forces concision↓ fewer output tokens
Stream responses↑ perceived speed= same quality= same cost
Prompt caching↓↓ on cache hit= same quality↓ 90% on cached tokens
Add CoT↑ more output tokens↑↑ significant for reasoning↑ more output tokens
The Prompt Caching Multiplier

Both Anthropic and OpenAI support prompt caching: if your system prompt is identical across requests, the KV cache is reused :: reducing latency by 50–80% and cost by up to 90% on those tokens. Design long system prompts to be stable (no per-request dynamic content) and front-loaded (put dynamic content at the end, after the cacheable prefix).
