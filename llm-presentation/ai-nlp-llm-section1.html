1.1

Artificial Intelligence vs Machine Learning vs Deep Learning

These three terms are often used interchangeably, but they describe different scopes within the same field. Understanding their relationship is foundational to everything that follows.

Think of the three as nested circles :: AI is the broadest concept, ML lives inside it, and Deep Learning is a specialized subfield of ML.

Concept
What It Is
Example

Artificial Intelligence

AI

The broad science of creating machines that can simulate human intelligence :: reasoning, problem-solving, perceiving, and learning.

Any technique that enables a computer to mimic cognitive functions. Includes rule-based systems, search algorithms, planning, and learning-based approaches.

Chess engine (Deep Blue)
Voice assistants (Siri)

Machine Learning

ML

A subset of AI where systems learn from data to improve at tasks without being explicitly programmed for each rule.

Algorithms detect patterns in training data and generalize to unseen inputs. Three paradigms: supervised, unsupervised, and reinforcement learning.

Spam filters
Recommendation systems
Fraud detection

Deep Learning

DL

A subset of ML using multi-layer artificial neural networks to learn hierarchical representations of data automatically.

Inspired by the brain, neural networks with many layers (hence "deep") can learn complex features directly from raw data like pixels or tokens :: no manual feature engineering.

Image recognition (CNNs)
Text generation (LLMs)
AlphaFold
Key Insight

The rise of deep learning after 2012 (ImageNet breakthrough) and the explosion of compute & data are what make modern AI :: including LLMs :: possible. Deep learning removes the need for hand-crafted features; the model learns representations end-to-end.

1.2

Generative AI Overview

Generative AI is a category of AI that can create new content :: text, images, audio, code, video :: rather than just classifying or predicting existing data.

GWhat Makes AI "Generative"?

Traditional ML models are primarily analytical: they take input data and produce a prediction or classification. A spam classifier predicts "spam or not spam". A credit scoring model predicts default probability.

Generative models, by contrast, learn the underlying distribution of data and can then sample from that distribution to produce new, realistic instances. They answer: "What does this data look like?" rather than "Which bucket does this belong to?"

2014 :: Generative Adversarial Networks (GANs)

Goodfellow et al. propose a generator/discriminator setup where two networks compete. Enabled realistic image synthesis for the first time.

2017 :: Transformers ("Attention Is All You Need")

Vaswani et al. at Google introduce the Transformer architecture :: the backbone of all modern LLMs. Attention mechanisms replace recurrence, enabling massive parallelism.

2018–2020 :: GPT-1, BERT, GPT-2, GPT-3

OpenAI and Google demonstrate that pre-training large Transformers on internet text, then fine-tuning, achieves state-of-the-art on nearly every NLP benchmark.

2021–2022 :: DALL·E, Stable Diffusion, InstructGPT

Generative AI explodes beyond text to images. RLHF (Reinforcement Learning from Human Feedback) makes LLMs safe and instruction-following.

2022–Present :: ChatGPT, GPT-4, Claude, Gemini, Llama

Generative AI enters mainstream. Multimodal models handle text, image, audio, and video. Open-source models become competitive with proprietary ones.

1.3

Discriminative vs Generative Models

Two fundamental paradigms in ML have very different goals, strengths, and use cases. Understanding this distinction clarifies where LLMs fit in the landscape.

🔍 Discriminative Models
  • Learn decision boundaries between classes: P(Y|X)
  • Map inputs to outputs (labels, classes, values)
  • Optimized for classification and regression tasks
  • Generally simpler, faster, needs less data
  • Cannot generate new examples
Examples:
Logistic Regression, SVM, Random Forests, BERT (for classification), CNNs for image classification
✨ Generative Models
  • Learn the full joint distribution of data: P(X, Y) or P(X)
  • Can sample new examples from learned distribution
  • Suited for content creation, data augmentation, simulation
  • Generally more complex, data-hungry, computationally expensive
  • Can perform classification via Bayes' rule
Examples:
GPT-4, Claude, Gemini (text); DALL·E, Midjourney (images); Suno, MusicGen (audio); GANs, VAEs (general)
Aspect Discriminative Generative
Goal Separate classes / predict labels Model data distribution, generate new data
Learns P(Y | X) :: conditional P(X, Y) or P(X) :: joint / marginal
Output Label, class, score, value New text, image, audio, code
Training data Often labeled pairs (X, Y) Large unlabeled corpora + optional fine-tuning
Risk Poor on out-of-distribution inputs Hallucination, reproducing training data
Use case Spam detection, sentiment, fraud Chatbots, code generation, image synthesis
Modern Trend

Many frontier models blur this boundary. GPT-4 and Claude are generative but can be fine-tuned as classifiers. BERT is discriminative but was pre-trained generatively (masked language modeling). The boundary is increasingly architectural rather than categorical.

1.4

Why LLMs Matter

Large Language Models represent a paradigm shift :: not just in NLP, but in how software is built, how knowledge is accessed, and what automation is possible.

?What is an LLM?

A Large Language Model is a deep learning model (specifically a Transformer) trained on massive text corpora to predict the next token given prior context. From this deceptively simple objective emerges remarkable emergent capability: reasoning, coding, translation, summarization, and conversation.

Key characteristics that define an LLM:

Scale

Billions of parameters

Trained on trillions of tokens from the web, books, and code. Scale alone drives emergent capabilities not present in smaller models.

Pretraining + RLHF

Two-phase training

Self-supervised pretraining on raw text, followed by fine-tuning with human feedback (RLHF) to make models helpful, harmless, and honest.

In-context Learning

No retraining needed

LLMs can perform new tasks from examples in the prompt alone :: zero-shot or few-shot :: without gradient updates. This is unprecedented in ML.

★Why This Is a Paradigm Shift

  1. General-purpose foundation

    One model handles translation, summarization, coding, Q&A, analysis :: previously each required a specialized model with custom training data.

  2. Natural language as interface

    For the first time, non-programmers can direct computers in plain English. This democratizes software capability to everyone with a keyboard.

  3. Knowledge compression at scale

    LLMs distill knowledge from billions of documents into model weights, enabling instant retrieval and synthesis across domains.

  4. Reasoning and planning

    Chain-of-thought prompting unlocks multi-step logical reasoning, enabling LLMs to tackle problems that require planning :: not just retrieval.

  5. Agentic automation

    LLMs can call tools, browse the web, write and execute code, and coordinate with other models :: enabling fully autonomous workflows (agents).

Limitations to Know

LLMs have a training cutoff and can hallucinate facts confidently. They don't have real-time access to data (unless augmented with retrieval/tools), struggle with precise arithmetic, and can be biased by training corpora. Knowing these limitations is as important as knowing capabilities.

Hands-on: Call the OpenAI API

Theory becomes intuition when you make your first API call. Below is a complete, annotated example of generating text completions with OpenAI's Chat Completions API.

1Setup & Installation

Install the OpenAI Python library and set your API key as an environment variable. Never hardcode API keys in source code.

terminal
BASH 
# Install the library
pip install openai

# Set API key in your environment
export OPENAI_API_KEY="sk-your-key-here"

# Verify installation
python -c "import openai; print(openai.__version__)"

2Basic Text Completion

The core API call uses chat.completions.create(). Messages are structured as a list of role/content pairs.

basic_completion.py
PYTHON 
from openai import OpenAI

# Initialize client (reads OPENAI_API_KEY from env)
client = OpenAI()

# Create a chat completion
response = client.chat.completions.create(
    model="gpt-4o",          # The model to use
    messages=[
        {
            "role": "system",   # System sets the assistant's behavior
            "content": "You are a helpful AI tutor teaching students about machine learning."
        },
        {
            "role": "user",     # User is the human turn
            "content": "Explain what a neural network is in 3 sentences."
        }
    ],
    temperature=0.7,          # 0=deterministic, 1=creative, 2=chaotic
    max_tokens=256,           # Limit response length
)

# Extract the assistant's reply
reply = response.choices[0].message.content
print(reply)

# Inspect token usage (cost awareness)
print(f"\nTokens used: {response.usage.total_tokens}")
print(f"Prompt: {response.usage.prompt_tokens} | Completion: {response.usage.completion_tokens}")

3Streaming Responses

For real-time output (like ChatGPT's typing effect), use stream=True. Chunks arrive as Server-Sent Events.

streaming.py
PYTHON 
from openai import OpenAI

client = OpenAI()

# Enable streaming
stream = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Write a haiku about neural networks."}],
    stream=True,  # 👈 This is the key change
)

for chunk in stream:
    if chunk.choices[0].delta.content is not None:
        print(chunk.choices[0].delta.content, end="", flush=True)

print()  # newline at end

4Key Parameters Reference

Parameter Type Range Effect
model string gpt-4o, gpt-4o-mini… Which model to invoke. Affects cost, speed, capability.
temperature float 0.0 – 2.0 Controls randomness. 0 = deterministic. Use low (0.2) for factual tasks, high (0.8+) for creative.
max_tokens integer 1 – 128K Max tokens to generate. Prevents runaway responses and controls cost.
top_p float 0.0 – 1.0 Nucleus sampling :: only consider top p% probability mass. Alternative to temperature.
frequency_penalty float -2.0 – 2.0 Penalizes repetition of tokens already used. Positive = less repetition.
system (message role) string :: Sets the assistant's persona and rules. Applied before user messages. Critical for prompt engineering.

5Error Handling Best Practices

robust_completion.py
PYTHON 
import openai
from openai import OpenAI
import time

client = OpenAI()

def safe_completion(prompt: str, max_retries: int = 3) -> str:
    """Robust API call with retry logic and error handling."""
    
    for attempt in range(max_retries):
        try:
            response = client.chat.completions.create(
                model="gpt-4o",
                messages=[{"role": "user", "content": prompt}],
                timeout=30,  # 30s timeout
            )
            return response.choices[0].message.content
            
        except openai.RateLimitError:
            print(f"Rate limited. Waiting {2 ** attempt}s...")
            time.sleep(2 ** attempt)  # exponential backoff
            
        except openai.AuthenticationError:
            raise ValueError("Invalid API key. Check OPENAI_API_KEY.")
            
        except openai.BadRequestError as e:
            print(f"Bad request: {e}")  # content policy, token limit exceeded, etc.
            break
            
    return "Failed to generate response after retries."
Production Tip

Always implement exponential backoff for rate limits, set explicit timeouts, log token usage for cost monitoring, and never expose API keys in client-side code. Use environment variables or a secrets manager in all environments.
