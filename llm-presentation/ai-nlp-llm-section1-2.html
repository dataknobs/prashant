  • If-then logic for parsing sentences

  • Similar words cluster in vector space

  • ✓ Transfers across tasks

  • ✗ Sequential :: can't parallelise
  • ✗ Struggles with long dependencies (even LSTMs)

Core idea
  • Attend to all tokens simultaneously
  • Self-attention + positional encoding
  • Scale unlocks emergent capabilities

  • ✓ Fully parallel training
  • ✓ Context-aware per token (dynamic embeddings)

1.2.1

Rule-based NLP

The first approach to language understanding was the most intuitive: write explicit rules. Linguists encoded grammar, morphology, and semantics by hand.

Rule-based NLP dominated from the 1950s through the 1980s. Systems like ELIZA (1966, MIT) used pattern-matching scripts to simulate conversation. SHRDLU (1970) understood natural language commands in a limited blocks-world domain using a hand-crafted grammar.

The defining tool of this era was the Context-Free Grammar (CFG) :: a set of rewrite rules that parse sentences into syntactic trees. Alongside CFGs, researchers built lexicons (hand-curated word lists with part-of-speech tags) and regular expressions for pattern extraction.

rule_based_nlp.py
PYTHON 
import re

# Rule-based approach: regex patterns + hand-crafted lexicon

# Named entity rules (hand-written)
PATTERNS = {
    "DATE":    re.compile(r'\b\d{1,2}/\d{1,2}/\d{2,4}\b'),
    "EMAIL":   re.compile(r'\b[\w.+-]+@[\w-]+\.[a-z]{2,}\b'),
    "MONEY":   re.compile(r'\$[\d,]+(?:\.\d{2})?'),
    "GREETING": re.compile(r'\b(hello|hi|hey|greetings)\b', re.IGNORECASE),
}

# Sentiment lexicon (hand-labelled)
POSITIVE = {"good", "great", "excellent", "love", "perfect", "wonderful"}
NEGATIVE = {"bad", "terrible", "awful", "hate", "broken", "worst"}

def rule_sentiment(text: str) -> str:
    words = set(text.lower().split())
    pos = len(words & POSITIVE)
    neg = len(words & NEGATIVE)
    if pos > neg: return "POSITIVE"
    elif neg > pos: return "NEGATIVE"
    else: return "NEUTRAL"

# Problem: "not good" → still classified as POSITIVE ❌
print(rule_sentiment("The product is not good at all"))  # → POSITIVE (wrong!)
print(rule_sentiment("This is an excellent purchase"))     # → POSITIVE ✓
Why Rule-based Systems Failed to Scale

Language is infinite and ambiguous. Rules that work for one domain break in another. Maintaining thousands of hand-crafted rules becomes impossible, and rules can't handle novel phrasing, slang, or domain shift. The solution: learn from data instead.

1.2.2

Statistical NLP

The 1990s shift to statistical methods transformed NLP. Instead of encoding rules, systems learn probability distributions over text corpora.

BBag of Words (BoW)

The simplest statistical text representation. A document is modelled as an unordered multiset of its words :: the "bag". Word order and grammar are discarded entirely.

Given a vocabulary V, each document becomes a vector of length |V| where each dimension is the word count (or binary presence).

Bag of Words :: Visual

CONCEPT
BoW Limitation

"The dog bit the man" and "The man bit the dog" have identical BoW representations. Discarding order discards meaning. This is the core weakness that TF-IDF doesn't fix :: it requires richer representations.

TTF-IDF

Term Frequency–Inverse Document Frequency improves on raw counts by weighting words by how informative they are across a corpus. Common words like "the" appear everywhere and carry little signal; rare words like "photosynthesis" are highly discriminative.

TF-IDF Formula

FORMULA
Term Frequency
TF(t,d) = count(t in d)
──────────────────
total words in d
How often term t appears in document d.
Inverse Document Frequency
IDF(t) = log( N / df(t) )
N = corpus size; df(t) = documents containing t. Rare terms → high IDF.
TF-IDF(t, d) = TF(t, d) × IDF(t)
1.2.3

Word Embeddings

The 2013 Word2Vec paper by Mikolov et al. at Google was a watershed moment. For the first time, words were represented as dense, meaningful vectors where geometric distance captured semantic relationships.

WWord2Vec

Word2Vec learns embeddings by training a shallow neural network on a self-supervised task: given a word, predict its context (Skip-gram), or given context, predict the word (CBOW). The hidden layer weights become the embeddings.

The stunning result: vector arithmetic captures analogy. king − man + woman ≈ queen. The geometry of the embedding space encodes semantic structure.

1.2.4

Sequence Models: RNN, LSTM, Seq2Seq

Word embeddings gave us better representations, but NLP tasks require understanding sequences. Recurrent Neural Networks process text token-by-token, maintaining a hidden state that accumulates context.

RRecurrent Neural Networks (RNN)

An RNN processes each input token x_t and produces a hidden state h_t that encodes all previous context. The same weights are applied at every timestep :: the network is recurrent.

RNN Unrolled Through Time

ARCHITECTURE
The Vanishing Gradient Problem

During backpropagation, gradients are multiplied through each timestep. Over long sequences, gradients shrink exponentially :: the network effectively forgets early context. "The trophy didn't fit in the bag because it was too big" :: an RNN may lose track of what "it" refers to by the time it processes the pronoun.

LLong Short-Term Memory (LSTM)

Hochreiter & Schmidhuber (1997) introduced the LSTM to solve vanishing gradients. Instead of a single hidden state, LSTMs maintain a cell state :: a conveyor belt that carries information across many timesteps, selectively updated by learned gates.

LSTM Gates

ARCHITECTURE
Forget Gate σ

Decides what to discard from cell state.

fₜ = σ(Wf·[hₜ₋₁,xₜ]+bf)
0 = forget all
1 = keep all
Input Gate σ + tanh

Decides what new info to store in cell state.

iₜ = σ(Wi·[hₜ₋₁,xₜ]+bi)
C̃ₜ = tanh(Wc·[hₜ₋₁,xₜ]+bc)
Cₜ = fₜ*Cₜ₋₁ + iₜ*C̃ₜ
Output Gate σ

Decides what to output from cell state.

oₜ = σ(Wo·[hₜ₋₁,xₜ]+bo)
hₜ = oₜ * tanh(Cₜ)

SSeq2Seq Architecture

Sutskever et al. (2014) introduced the Sequence-to-Sequence model :: an encoder-decoder architecture. The encoder compresses the input sequence into a fixed-size context vector; the decoder generates the output sequence token by token conditioned on it.

Seq2Seq powered the first wave of neural machine translation (Google Translate, 2016) and enabled NLP tasks where input and output have different lengths: translation, summarisation, Q&A.

The Information Bottleneck Problem

Compressing an entire sentence into one fixed-size vector loses information. For long sequences, the decoder "forgets" early parts of the input. This bottleneck motivated the attention mechanism :: letting the decoder dynamically focus on different parts of the encoder output at each generation step.

1.2.5

The Attention Revolution

Bahdanau et al. (2015) proposed attention as an add-on to Seq2Seq. Instead of a fixed context vector, the decoder learns to attend to different encoder positions at each decoding step.

Attention computes a weighted sum over encoder hidden states. The weights :: attention scores :: are learned, indicating how relevant each input position is when generating the current output token.

This was transformative: attention made the information bottleneck optional. The decoder could access the full encoder sequence at any step. NMT quality improved dramatically, and the mechanism became interpretable :: attention matrices show which source words the model looks at when translating each target word.

Scaled Dot-Product Attention

FORMULA
Attention(Q, K, V) = softmax( QKᵀ / √dₖ ) · V
Q :: Queries "What am I looking for?" :: the current token's representation as a search query.
K :: Keys "What do I contain?" :: index labels for each position. Q·Kᵀ = similarity score.
V :: Values "What I actually contribute" :: the content retrieved when a key is matched.
√dₖ scaling prevents dot products from growing too large in high dimensions, keeping softmax gradients stable.
1.2.6

Transformers: "Attention Is All You Need"

Vaswani et al. (Google, 2017) made the radical observation: you don't need recurrence at all. Replace the entire RNN with only attention mechanisms, scaled up. This is the Transformer.

The key insight: self-attention lets every token attend to every other token in the sequence simultaneously :: with no sequential dependency. This allows full parallelism during training, enabling models to scale to unprecedented size.

Transformer Block (Simplified)

ARCHITECTURE
CapabilityRNN / LSTMTransformer

Key Concepts at a Glance

Every term from the curriculum :: with precise definitions, the intuition behind them, and their mathematical form.

Statistical Era

Bag of Words

Represent a document as a count vector over a fixed vocabulary. Word order is discarded; only frequency matters.

doc = [count(w₁), count(w₂), ...]
Dim: |Vocabulary| (sparse)
Statistical Era

TF-IDF

Weights word counts by how rare they are across the corpus. Downweights stop words; upweights domain-specific terms.

TF-IDF(t,d) = TF(t,d) × log(N/df(t))
Better signal-to-noise than raw BoW
Embedding Era

Word2Vec

Train shallow neural net to predict context from word (Skip-gram) or word from context (CBOW). Hidden weights = embeddings.

king − man + woman ≈ queen
Dim: 50–300 (dense)
Sequence Era

RNN

Process tokens sequentially, updating a hidden state at each step. Same weights at every timestep. Suffers vanishing gradients.

hₜ = tanh(Wₓxₜ + Wₕhₜ₋₁ + b)
yₜ = Wᵧhₜ + bᵧ
Sequence Era

LSTM

Adds cell state and three gates (forget, input, output) to selectively remember / forget over long sequences.

Cell state Cₜ = fₜ⊙Cₜ₋₁ + iₜ⊙C̃ₜ
Gates use sigmoid (0–1 control)
Sequence Era

Seq2Seq

Encoder compresses input sequence to context vector; decoder generates output token-by-token. Foundation of NMT.

Encoder: {x₁…xₙ} → c
Decoder: c → {y₁…yₘ}
+Attention → no bottleneck
1.2.8

Hands-on: TF-IDF vs Embeddings

The best way to understand the difference between TF-IDF and semantic embeddings is to see them side-by-side. Below: production Python code, and an interactive live demo powered by an LLM.

1TF-IDF Implementation from Scratch

tfidf_scratch.py
PYTHON 
import math
from collections import Counter
import numpy as np

# ── Sample corpus ──
corpus = [
    "The cat sat on the mat",
    "The dog ran across the park",
    "Neural networks learn from data",
    "Deep learning uses neural networks",
    "The cat and the dog are friends",
]

def tokenize(text): return text.lower().split()

def build_vocab(corpus):
    return sorted(set(w for doc in corpus for w in tokenize(doc)))

def tf(doc_tokens, word):
    return doc_tokens.count(word) / len(doc_tokens)

def idf(corpus_tokens, word):
    N = len(corpus_tokens)
    df = sum(1 for doc in corpus_tokens if word in doc)
    return math.log((N + 1) / (df + 1)) + 1  # smoothed IDF

def tfidf_vector(doc_tokens, vocab, idf_scores):
    return np.array([
        tf(doc_tokens, word) * idf_scores[word]
        for word in vocab
    ])

# Build
corpus_tokens = [tokenize(doc) for doc in corpus]
vocab          = build_vocab(corpus)
idf_scores    = {w: idf(corpus_tokens, w) for w in vocab}
tfidf_matrix  = np.array([tfidf_vector(t, vocab, idf_scores) for t in corpus_tokens])

# Cosine similarity function
def cosine_sim(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b) + 1e-8)

# Query: find most similar doc to "machine learning neural"
query    = "machine learning neural"
q_tokens = tokenize(query)
q_vec    = tfidf_vector(q_tokens, vocab, idf_scores)

for i, doc_vec in enumerate(tfidf_matrix):
    sim = cosine_sim(q_vec, doc_vec)
    print(f"Doc {i}: {sim:.3f} :: {corpus[i]}")

# Output:
# Doc 0: 0.000 :: "The cat sat on the mat"      ← no "neural" or "learning"
# Doc 2: 0.612 :: "Neural networks learn..."     ← high match ✓
# Doc 3: 0.489 :: "Deep learning uses..."        ← partial match
# Problem: "cat" and "feline" → similarity=0 ❌ (no semantics)

2Embeddings with Sentence Transformers

embeddings_comparison.py
PYTHON 
from sentence_transformers import SentenceTransformer
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity

# Load a pre-trained sentence embedding model
model = SentenceTransformer("all-MiniLM-L6-v2")  # 22M params, fast

corpus = [
    "The cat sat on the mat",
    "The dog ran across the park",
    "Neural networks learn from data",
    "Deep learning uses neural networks",
    "The feline rested on the rug",   # ← "cat" synonym
]

# Encode entire corpus into 384-dim vectors
embeddings = model.encode(corpus, normalize_embeddings=True)

# Query: semantically search
query     = "a kitty lounging on a floor covering"  # zero lexical overlap!
q_emb     = model.encode([query], normalize_embeddings=True)
scores    = cosine_similarity(q_emb, embeddings)[0]

for i, (score, doc) in enumerate(zip(scores, corpus)):
    print(f"Doc {i}: {score:.3f} :: {doc}")

# Output:
# Doc 0: 0.721 :: "The cat sat on the mat"        ← high ✓ (semantic match)
# Doc 4: 0.698 :: "The feline rested on the rug"  ← high ✓ (synonym match!)
# Doc 2: 0.183 :: "Neural networks learn..."       ← low ✓
#
# TF-IDF score for same query: ALL 0.000 (no word overlap at all!)
# This is the POWER of embeddings: semantic similarity without shared words.

# Key insight: embedding dim is fixed at 384, not |vocabulary|
print(f"\nEmbedding shape: {embeddings.shape}")  # (5, 384)
print(f"TF-IDF shape would be: (5, {len(vocab)})")   # (5, 50000+)
The Key Difference :: Illustrated

TF-IDF gives "cat" and "feline" a similarity of 0 :: they share no characters. A sentence embedding model gives them a similarity of ~0.85 :: because they appear in similar contexts in training data. This is the leap from symbolic to neural representation.
